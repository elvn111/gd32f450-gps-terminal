# GD32F450 GPS 命令系统说明

> 适用工程：`GD32F4xx_Firmware_Library_V3.3.3\Template`（Keil 工程 `Keil5_project\Project.uvprojx`）
> 目标芯片：GD32F450IK（Cortex-M4F，3 MB Flash / 192 KB SRAM）· RTOS：FreeRTOS v10.1.1
> 编译器：ARMCC V5.06 update 7（C99 + MicroLIB）· 命令系统版本：CLI v1.0.0
> 附录 A 为 **GPS 下行链路**（转发给第二颗 MCU 的二进制协议），完整协议规范见同目录 `GD32F450_串行接口协议规范.md`
> 最后更新：2026-10-14

---

## 1. 这是什么

一套跑在 **USART0（PC 上位机）** 上的串口命令行，用来：

- **改配置**：输出模式、回显、调试打印开关、有效定位卫星数门限、GPS 波特率；
- **操作 GPS**：透传 Unicore 命令、设置输出语句与频率、重启/保存/查询版本、查看最近一次定位；
- **看现场**：DMA 通道状态、任务栈水位、统计数据、Flash 配置记录状态；
- **存配置**：`save` / `load` 落到片内 Flash（掉电不丢）。

GPS 挂在 **USART5** 上，两路串口**都用 DMA 接收**，互不冲突（见第 3 节的通道分配）。

## 2. 硬件与接口

| 项目 | 配置 |
|---|---|
| 控制台串口 | **USART0**：PA9(TX) / PA10(RX)，AF7，**115200-8-N-1**，无流控 |
| GPS 串口 | **USART5**：PC6(TX) / PC7(RX)，AF8，115200-8-N-1 |
| 心跳灯 | **PA15**（`gd32f450i_eval` BSP 的 `LED1`，**引脚接阳极：高电平点亮**） |
| 调试口 | SWD（PA13/PA14） |

### 2.1 DMA 通道分配（依据《GD32F4xx User Manual Rev3.4》Table 10-3）

| 用途 | DMA | 通道 | PERIEN[2:0] | 说明 |
|---|---|---|---|---|
| **USART0_RX** | DMA1 | **CH5** | `0b100` | 控制台接收（备选通道为 CH2） |
| **USART5_RX** | DMA1 | **CH2** | `0b101` | GPS 接收（备选通道为 CH1） |
| USART0_TX | DMA1 | CH7 | `0b100` | **空闲**，将来做 printf 的 DMA 发送 |
| USART5_TX | DMA1 | CH6/CH7 | `0b101` | 目前用阻塞发送 |

手册同时规定：*同一外设请求的两个备选通道**不允许同时使能***（例如 `CH2+PERIEN4` 与 `CH5+PERIEN4` 不能一起开）。当前实现按上表错开，两路 RX DMA 可同时工作。

### 2.2 缓冲区

| 变量 | 大小 | 用途 |
|---|---|---|
| `usart0_rx_buf` | 1024 | USART0 RX DMA 的目标缓冲（DMA 每段都从基址重新装载） |
| `usart0_ring` | 2048 | 控制台输入的环形缓冲：IDLE 中断写入，`RX_Task` 取走交给 CLI |
| `usart5_rx_buf` | 1024 | USART5 RX DMA 的目标缓冲 |
| `usart5_frame_buf` | 1024 | 交给 `GPSRX_Task`/解析器的副本 |

均定义在 `buff_config.h` 中（含通道/子外设/长度宏）。

## 3. 软件架构

```
        USART0 RX ──DMA1 CH5──► usart0_rx_buf ──IDLE 中断──► 信号量 + 帧长
                                                                  │
                                                            RX_Task (任务上下文)
                                                                  │ cli_input(buf,len)
        ┌─────────────────────────────────────────────────────────┴──────────────────────────┐
        │ 行装配(\r \n \b \t Ctrl+C Ctrl+L, ESC[A/B 历史) → 分词 → 命令表 → 处理函数         │
        └─────────────────────────────────────────────────────────┬──────────────────────────┘
                    printf()  ──► USART0 TX (fputc)          gps_send_line() ──► USART5 TX
                                                                       │
        USART5 RX ──DMA1 CH2──► usart5_rx_buf ──IDLE 中断──► 信号量 ──► GPSRX_Task
                                                                       │ memcpy
                                                                       ▼
                                                                 TX_Task + gps_info_rsl()
```

**四条设计原则**（也是代码为什么长这样）：

1. **中断只搬数据，绝不解析**。ISR 只做：清 IDLE、快照帧长、给信号量、重装 DMA。没有一行解析代码；
2. **解析全部在任务里**。所以可以安全调用 `printf`、阻塞发送、FreeRTOS API；
3. **全程定长静态缓冲**。不用 `malloc`、不用 `strtok`（不可重入且会改原串），行缓冲最大 95 字符 + 12 个参数；
4. **表驱动**。加命令 = 加一行表项；加配置项 = 加一行表项，`get`/`set`/范围校验/帮助自动生效。

**平台钩子（`cli_platform_t`）**是解耦的关键：解释器不认识 USART5、不认识 `GPS_Info`，只认 15 个函数指针。任何钩子传 `NULL`，对应命令会明确回 `hook not implemented`。换板子/换模块只改 `main.c` 里的 `plat_*`。

## 4. 快速上手

1. USB-TTL 接 PA9/PA10（交叉），打开串口助手：**115200 / 8 / N / 1**，勾选 **回车换行（CRLF）**，关闭"本地回显"；
2. 复位板子，应看到：

   ```
   [cli] GD32F450 GPS console v1.1.0, type 'help'
   > 
   ```

3. 依次敲下面几条验证（`LED` 应 1 Hz 慢闪）：

   | 命令 | 期望现象 |
   |---|---|
   | `help` | 列出全部命令与配置项 |
   | `tasks` | 任务表，`stack` 列是各任务**剩余栈**（字），越小越危险 |
   | `dma` | 两路 RX：`chen=1`、`perien=4/5`、`left` 随收字节递减 |
   | `status` | 配置 + 收帧统计 + Flash 记录状态 |
   | `gps info` | 打印最近一次解出的定位（GPS 已定位时才有意义） |
   | `set verbose 0` | 关掉每秒的定位刷屏 |
   | `save` | 写入 Flash，随后 `status` 里 `[nvm] ... seq=1` |

## 5. 命令参考

### 5.1 通用

| 命令 | 参数 | 说明 |
|---|---|---|
| `help` / `?` | `[命令或配置项]` | 无参列出全部；带参查单条 |
| `ver` | – | 版本、编译日期时间、运行时长 |
| `status` | – | 配置、收帧/命令/GPS 解析统计、DMA 剩余、Flash 记录状态 |
| `tasks` | – | 任务表（名称/状态/优先级/**栈水位**/编号），来自 `vTaskList()` |
| `dma` | – | USART0/USART5 RX 通道：`chen` `cmen` `perien` `left` `ftf` |
| `clr` | – | 统计计数清零 |
| `reboot` | – | 软复位（`NVIC_SystemReset`） |

### 5.2 配置

| 命令 | 参数 | 说明 |
|---|---|---|
| `get` | `[项]` | 无参列出全部配置；带参看单项 |
| `set` | `<项> <值>` | 改配置，带范围校验；有副作用的项立即生效 |
| `mode` | `raw` \| `worked` | `set mode` 的快捷方式 |
| `out` | `off` \| `raw` \| `parsed` | **下行链路内容**：不发 / GPS 原报文 / 二进制解析帧 |
| `auto` | `off` \| `fix` \| `tick [hz]` | **下行触发**：仅手动 / 每个新定位 / 定时心跳，可同时给 Hz |
| `fix` | – | 立刻发一次最新值（`auto off` 时用） |
| `send default` | – | **把下行发送三项恢复出厂默认**（`out=parsed`、`auto=fix`、`rate=20`），不动其它配置；仅 RAM，`save` 才持久 |
| `gstat` | – | 控制台 + 下行链路统计（含 `dropped(latest)`） |
| `info` | – | 立刻向对端发一帧终端信息（命令码 `0x01` / 功能码 `0x02`：版本、上电时长、计数器、当前下行配置） |
| `bridge` | `on` \| `off` | **透明桥**：GPS↔本口双向字节透传，**期间不再受理任何命令**（退出：静默 ≥1 s 后发 `+++`，或复位） |
| `default` | – | 恢复默认配置（**仅 RAM**，要持久化再 `save`） |
| `save` | – | 写入片内 Flash（追加记录，快速） |
| `load` | – | 从 Flash 读回并应用，随后打印全部配置 |

### 5.3 GPS 操作

| 命令 | 实际发给模块的内容 | 说明 |
|---|---|---|
| `gps <命令...>` | 原样 + CRLF | 通用透传，例：`gps log com1 gpnav ontime 1` |
| `gps log <语句> <Hz>` | `log com1 <语句> ontime <Hz>` | 例：`gps log gpnav 5` → 5 Hz 输出 GPNAV |
| `gps unlog` | `unlogall` | 关闭全部输出 |
| `gps save` | `saveconfig` | 模块侧配置存进模块自己的 Flash |
| `gps ver` | `version` | 查询模块版本 |
| `gps scene <名>` | `set appscene <名>` | 例：`gps scene survey` |
| `gps baud <速率>` | `config com1 <速率>`，随后**本地 USART5 同步切换** | 见 8.3 的顺序注意事项 |
| `gps hwreset` | 无（拉低 PB4 再释放） | 硬复位模块，等它启动后自动重发预设命令 |
| `gps freset` | `freset` | 模块**恢复出厂**（清除模块内已保存配置，谨慎使用） |
| `gps reset` | 已移除 | 只回提示，不做任何动作 |
| `gps init` | `GPS_CMD[]` 预设表（4 条） | 与上电时相同 |
| `gps info` | 本地打印 | 打印最近一次解析出的经纬度/高程/航向/基线/卫星数，并按 `sat_min` 判定 valid/invalid |

## 6. 配置项参考

| 名称 | 类型 | 范围 | 默认 | 副作用 |
|---|---|---|---|---|
| `mode` | u8 | 0..1 | 1 | `0=RAW` 原始数据直出，`1=WORKED` 输出解析结果；立即改 `OUTPUT_STATE` |
| `echo` | u8 | 0..1 | 1 | 1 = 回显输入 + `> ` 提示符；做机机对接/脚本时设 0 |
| `verbose` | u8 | 0..1 | **0** | 1 = 每次解析都打印 6 行定位数据；0 = 安静（**出厂默认 0**） |
| `sat_min` | u8 | 0..40 | 4 | 定位有效所需最少卫星数：参与下行帧 `flag.bit0` 的判定，也用于 `gps info` 显示 |
| `gps_baud` | u32 | 9600..921600 | 115200 | 改动会**立即重配 USART5**（模块侧波特率需另行 `gps baud` 或模块自协商） |
| `out` | u8 | 0..2 | **2** | 下行内容：0=off 1=raw 原报文 2=parsed 二进制帧（**上电默认就上报**） |
| `auto` | u8 | 0..2 | **1** | 下行触发：0=off 1=新定位 2=定时心跳（**上电默认每个新值都发**） |
| `rate` | u16 | 1..20 | **20** | 下行限流/心跳频率 (Hz)；低于 2 时每秒只能出一帧（两句定位连着到） |
| `prefix` | u8 | 0..126 | 64 (`@`) | **上行前缀**：以此字符开头的行整行转给 GPS 模块，0=关闭 |

## 7. 配置持久化（Flash）

### 7.1 位置与几何

| 项 | 值 |
|---|---|
| 地址 | **0x08100000**（Flash bank 1 起始处，扇区名 12） |
| 扇区号（寄存器值） | `CTL_SN(16)` = 0x10 |
| 扇区大小 | 16 KB |
| 记录大小 | 24 字节（6 个字） |
| 槽位数 | 682 |

**为什么选这里**：
- 链接脚本 `Project.sct` 把镜像放在 `0x08000000`，当前镜像约 28 KB，bank 1 完全空闲；
- GD32F450 **没有 `fmc_page_erase()`**（该 API 只对 GD32F425/F427/F470 编译），只能用 `fmc_sector_erase()`；
- bank 0 的 16 KB 扇区（0x08000000~0x0800FFFF）被程序占用，bank 1 的 16 KB 扇区（0x08100000~0x0810FFFF）正好可用。

### 7.2 记录格式与追加日志

```
+0  magic  'NVM1' (0x4E564D31)      +8  size     sizeof(cli_config_t)
+4  version 1                       +12 sequence 每次保存 +1
+16 payload cli_config_t            +20 checksum 前 20 字节的旋转累加
```

- **追加写**：每次 `save` 只把下一条 24 字节记录写进下一个空槽，**不擦扇区**（微秒级）；
- **槽位写满**（682 次）才擦一次扇区，日志压缩为一条；
- `load` 扫描全部槽位，取**序号最大**且校验通过的那条；
- 因此**掉电最多丢最后一次**，上一条记录仍然有效；
- 每条记录写完后会**回读校验**（magic/version/size/checksum + 内容逐字节比对），写失败会报 `save failed (rc=-5/-7)`。

### 7.3 相关命令与错误码

| 命令/现象 | 说明 |
|---|---|
| `save` → `[nvm] 0x08100000 sector=16: seq=3, slot 2/3 used` | `slot x/y`：最新记录在槽 x，共用了 y 个槽 |
| `status` 里的 `[nvm] ...` | 同上，随 `status` 一起显示 |
| `rc=-3` | Flash 容量 < 2 MB（bank 1 不存在），拒绝写入 |
| `rc=-4` | 扇区擦除失败 |
| `rc=-5` | 字编程失败 |
| `rc=-6/-7` | 回读校验失败（内容不符） |
| `rc=-2`（load） | 没有任何有效记录（空片或已擦除） |

> 清空配置：`default` + `save`（会写入一条默认值记录），或用调试器擦掉 0x08100000 所在扇区。

## 8. GPS 操作指南

### 8.1 上电默认动作

> **上电即上报**：默认 `out=parsed`、`auto=fix`、`rate=20`、`verbose=0`。模块一开始输出定位语句，终端就把二进制帧发到 USART0（定位数据帧 `0x90/0x01`，每秒两帧）。
> 停机外发：`out off`；想看 6 行文本报告：`set verbose 1`。

`Init_Task` 里调用 `gps_init()`，按 `GPS_CMD[]` 依次发送：

```
unlogall
set appscene survey
log com1 gpnav ontime 1
log com1 gpybm ontime 1
```

共 4 条，**不含 `freset`**：那是模块恢复出厂，会清掉模块内 `saveconfig` 保存的配置并强制冷收敛，显著拖慢首次定位。需要时用 `gps freset` 手动发。

### 8.2 常用组合

```
gps ver                     ← 确认模块在线（会收到模块回包）
gps scene survey            ← 测量场景
gps log gpnav 5             ← 5 Hz 输出 GPNAV
gps log gpybm 1             ← 1 Hz 输出 GPYBM
set verbose 1               ← 打开解析结果打印
gps info                    ← 随时看最近一次定位
gps unlog                   ← 收工时关闭输出
gps save                    ← 让模块记住当前设置
```

### 8.3 改波特率的正确顺序

模块侧与 MCU 侧必须**同步**改，否则会瞬间失联：

1. `gps baud 460800` —— 本命令会先发 `config com1 460800` 给模块，**紧接着**把本地 USART5 切到 460800，并同步更新配置项 `gps_baud`；
2. 立刻 `gps save`（需要重新以 460800 通信成功才生效）；
3. 想永久保留，本地再 `save`；
4. **若失联**：把 `gps_baud` 改回 115200（`set gps_baud 115200`）或给模块断电重启恢复默认。

### 8.4 抓原始数据

```
set echo 0          ← 关回显，避免混入控制台字符
mode raw            ← 原始语句直出（注意：此时控制台会与原始数据抢串口）
```

RAW 模式下 `TX_Task` 直接打印 `usart5_frame_buf`；要看解析结果就切回 `mode worked`。
**建议**：抓数据时用另一路串口或用调试器观察 `usart5_frame_buf`，因为 RAW 数据与 CLI 提示符共用 USART0。

### 8.5 解析规则（`info_bsp.c`）

- 句子必须 `$GPNAV,` 或 `$GPYBM,` 开头，并以 `*XX` 结尾，`XX` 为 `$` 之后到 `*` 之前所有字符的**异或**（`Info_Check()` 校验）；
- 字段**按逗号位置**取值（字段 1 是语句名本身，不能"跳过非数字字段"，否则 `SN00016361`、`VN` 这类文本字段会让后面所有索引平移）：
  `$GPYBM` 用 ID4/5/6/7（位置、椭球高、航向）+ ID17/18（定位/定向状态）+ ID19（星数）+ ID22（基线）；
  `$GPNAV` 用 ID7/8/9（位置、海拔高）+ ID12（航向）+ ID19/20（状态）+ ID22（基线）+ ID23–27（星数求和）；
- 空字段表示**无效**而不是 0；校验和错、缺 `*`、字段数不足（GPYBM < 23、GPNAV < 22）整句丢弃；
- 接收侧先**按行组装**（`GPSRX_Task`）：跨块被切断的语句会补齐后再处理，因此解析与下行拿到的都是完整语句。

## 10. 扩展指南

### 10.1 加一条命令

```c
/* 1) 写处理函数（argc>=1，argv[0] 是命令名本身） */
static int cmd_led(int argc, char **argv)
{
    if ((argc != 2) || (0 != strcmp(argv[1], "on") && 0 != strcmp(argv[1], "off"))) {
        printf("[cli] usage: led on|off\r\n");
        return -1;
    }
    if (0 == strcmp(argv[1], "on")) { gd_eval_led_on(LED1);  }
    else                            { gd_eval_led_off(LED1); }
    return 0;
}

/* 2) 在 cli.c 的 s_cmds[] 里加一行（注意不要让名字互为前缀） */
{ "led", "led on|off          board LED heartbeat", cmd_led },
```

### 10.2 加一个配置项

```c
/* s_items[] 加一行：名称、类型、变量地址、最小值、最大值、帮助 */
{ "log_hz", CFG_U32, &s_cfg.log_hz, 0U, 50U, "GPS output rate in Hz" },
```

`get` / `set` / 范围校验 / `help` 输出自动生效；若该项有硬件副作用，在 `cfg_apply()` 里加对应处理。

### 10.3 加一个平台钩子（新外设/新动作）

1. `cli.h` 的 `cli_platform_t` 里加函数指针；
2. `main.c` 里实现 `plat_xxx()` 并写进 `g_cli_plat`（用**指定初始化器** `.name = ...`，不要用位置列表）；
3. 传 `NULL` 表示"本工程不支持"，命令会回 `hook not implemented`。

### 10.4 移植到别的工程/芯片

- 只需实现 `plat_*` 钩子 + 保证 `cli_input()` 有数据喂入（任何串口/DMA/中断方式都行）；
- `cli.c` / `cli.h` 不依赖 GD32 任何外设，只依赖 `printf`（重定向到控制台串口即可）；
- 注意目标编译器对**非 ASCII 字符串**的支持（见 11.1）。

## 11. 设计与约束（踩过的坑）

### 11.1 ARMCC V5 不接受字符串里的中文（重要）

用 AC5 编译时，源码中的**字符串字面量**里出现非 ASCII 字节会报：

```
#870-D: invalid multibyte character sequence
```

**更麻烦的是**：这条警告之后整个文件的语法解析会跑偏，接着出现一堆莫名其妙的
`#169: expected a declaration`。所以 `cli.c` / `cli.h` / `nvm_config.c` / `nvm_config.h`
全部**只写 ASCII**（注释也用英文）。中文注释在 `main.c` 里没问题（注释不参与字符串解析），
但字符串一律不要中文。用 AC6（armclang）则默认支持 UTF-8。

### 11.2 printf 不可重入 → 输出锁

`TX_Task`（定位打印）和 `RX_Task`（CLI 输出）都会 `printf`，MicroLIB 非线程安全。
现在用一个互斥量串行化：CLI 内部在 `cli_input()` / `cli_exec_line()` 入口取锁，
其它任务打印时用 `cli_out_lock()` / `cli_out_unlock()` 包住整段（`TX_Task` 的定位块已包好）。
**切记：不要嵌套调用 `cli_input()`**（非递归互斥量会死锁）。

### 11.3 任务栈

- 所有任务用 `TASK_STACK_WORDS = configMINIMAL_STACK_SIZE * 2`（= 260 words = **1040 字节**）；
- 原来 130 words（520 B）时，`printf` + CLI 调用链容易溢出；
- `configCHECK_FOR_STACK_OVERFLOW = 2` + `vApplicationStackOverflowHook()`：溢出会**快闪 LED**，
  任务名存进 `g_stack_overflow_task`；
- 随时用 `tasks` 命令看各任务剩余栈（`stack` 列，单位是**字**，持续接近 0 就要加大）。

### 11.4 RX：IDLE 中断取走数据 + 软件环形缓冲

USART0（控制台）与 USART5（GPS）都在 IDLE 中断里从 DMA 缓冲把这一段的字节取走，
再从基址重新装载 DMA 收下一段。区别在于取走之后放到哪里：

- **USART0 → 环形缓冲**（`usart0_ring`，2048 B）：中断写、`RX_Task` 读，单生产者单消费者，
  因此任务在跑长命令（`save` 的 Flash 擦写、`reboot`）期间到达的输入不会丢；
- **USART5 → 行组装缓冲**：`GPSRX_Task` 把新数据接到上一次的尾巴上，只把**完整语句**
  交给解析与下行，尾巴留到下一段（`GPS_LINE_CARRY_SIZE`）。

极端情况下环形缓冲写满会丢字节并计数，用 `status` / `dma` 命令的
`console ring: used=/overflow=` 观察。

### 11.5 行缓冲与分片

一次 DMA 帧可能含 0 行、半行或多行（`help\r\nstatus\r\n` 一次到齐，或 `sta` + `tus\r\n` 分两帧），
全部由 `cli_input()` 内部的行缓冲拼接，命令分发只见到完整行。

## 12. 故障排查

### 12.1 LED 语义（PA15，高电平点亮）

| 现象 | 含义 |
|---|---|
| **1 Hz 慢闪**（500 ms 亮 / 500 ms 灭） | 系统正常运行 |
| **快闪** | 任务栈溢出 → 调试器看 `g_stack_overflow_task` |
| **常亮/半亮** | 闪烁频率过高（历史问题：`vTaskDelay(1)` @1000 Hz tick = 500 Hz，肉眼看不见） |
| **全灭** | 死机（HardFault / 断言死循环），或 `Init_Task` 还没跑到 `gd_eval_led_init()` |

### 12.2 HardFault 现场变量

`HardFault_Handler` 会把现场存进这些全局变量，**调试器 Halt 后直接看**：

| 变量 | 含义 |
|---|---|
| `g_fault_pc_psp` / `g_fault_pc_msp` | 出错时压栈的 PC（任务上下文看 PSP，中断上下文看 MSP） |
| `g_fault_cfsr` | 可配置故障状态：`0x0002` DACCVIOL、`0x0100` IBUSERR、`0x0200` PRECISERR（野指针）、`0x0400` IMPRECISERR、`0x1000` UNDEFINSTR、`0x2000` INVSTATE |
| `g_fault_hfsr` | 硬故障状态（`0x40000000` = 由上面某项升级而来） |
| `g_fault_bfar` / `g_fault_mmfar` | 出错地址（对应 PRECISERR / DACCVIOL 时有效） |

### 12.3 常见现象 → 原因 → 处理

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 上电就死，串口一句不出 | 中断里给了还没创建的信号量 → `configASSERT` 关中断死循环 | 信号量必须在开中断**之前**创建；ISR 里加 `NULL` 判断（已修） |
| 敲第一个键后串口就没反应/重复回显旧字节 | RX DMA 被 disable 后再没重装（重装代码写在 RBNE 分支，而 USART0 没开 RBNE） | 在 IDLE 分支里重装（已修） |
| `gps info` 一直 Error / 解析永远失败 | 帧首字节丢失（CPU 读走的字节被 DMA 覆盖）→ `$` 没了，校验必失败 | 重装时指针回到 0（已修） |
| 控制台整段乱、日志交错 | 两个任务同时 `printf` | 用 `cli_out_lock()` / `cli_out_unlock()` 包住输出 |
| 随机死机、`tasks` 显示某任务 `stack` 接近 0 | 栈溢出 | 加大该任务栈；看 `g_stack_overflow_task` |
| `save` 报 `rc=-5/-7` | Flash 写/校验失败（电压、扇区被写保护） | 检查供电与写保护；`status` 看 `[nvm]` 是否有效 |
| `save` 报 `rc=-3` | 芯片 Flash < 2 MB（无 bank 1） | 改 `NVM_CONFIG_ADDR` 到可用扇区（并同步改扇区号） |
| `dma` 里 `chen=0` | 通道被关且未重装（或正处在 IDLE 处理窗口） | 收一个字节再看；若长期为 0 说明 IDLE 未触发或中断未使能 |
| 编译报 `#870-D` + 一堆 `#169` | 字符串里写了中文 | 把该文件改成纯 ASCII（见 11.1） |

### 12.4 三板斧

1. **Halt 看 PC**：停在 `configASSERT` 的 `for(;;)`（紧跟 `CPSID i`）→ 断言；停在 `HardFault_Handler` → 看 12.2 的变量；反复进出某 ISR → 中断标志没清；
2. **看 LED**：慢闪=活着，快闪=栈溢出，灭=死了或未初始化；
3. **敲命令**：`status` 看统计与 Flash 状态，`dma` 看接收通道是否在搬，`tasks` 看栈水位。

## 附录 A. GPS 下行链路（转发给第二颗 MCU）

**完整协议规范见 `GD32F450_串行接口协议规范.md`**（含帧样例字节、CRC 标准值、接收端参考代码）。
本节只讲发送端（本工程）的实现与用法。

### A.1 两种下行内容

| 配置 | 内容 | 特点 |
|---|---|---|
| `out raw` | GPS **原始报文**字节级透传 | **一条完整语句一帧**（含它自己的 CR/LF）；零解析零转换；接收端按行解析 |
| `out parsed` | **解析后**的二进制帧（32 B，CRC16） | 带宽小、抗干扰强；字段定标整数，无浮点/无结构体布局问题 |
| `out off` | 只喂解析器，不外发 | 默认值，保证串口是干净的控制台 |

> 注意区分两个"模式"：`mode raw|worked` 管**控制台**输出什么；`out off|raw|parsed` 管**下行链路**发什么。两者独立，可任意组合。

### A.2 触发方式（"保最新"，绝不排队）

| `auto` | 行为 |
|---|---|
| `off` | 只有敲 `fix` 才发一次 |
| `fix` | GPS 每来一帧新数据就发（受 `rate` 限流） |
| `tick` | 每 `1/rate` 秒发一次最新值（心跳，即使没有更新） |

- 发送端**只保留最新一份**数据；未发出去就被覆盖 → 计入 `dropped(latest)`（`gstat` 可见）；
- **不排队、不重传、不做流控**，所以延迟不会累积；
- `rate` 与 GPS 输出频率解耦：GPS 可以 5 Hz 输出，链路只发 1 Hz。

### A.3 实现要点（`gps_link.c`）

1. **发送通道**：`DMA1 CH7 + PERIEN 0b100`（USART0_TX，手册 Table 10-3），此前空闲；一帧 = 一次原子 DMA 搬运，CPU 只花"配 4 个寄存器"的时间；
2. **双缓冲（ping-pong）**：每类内容两份缓冲，发布时写"发送端没在用"的那一份 → DMA 读的缓冲**永远不会**被接收侧改写；
3. **与控制台共存（"边输出边敲命令"）**：
   - 每帧发送全程持有控制台输出锁 `cli_out_lock()`，所以 `> ` 提示符/回显**绝不会插进帧中间**；
   - 锁的释放条件是 **DMA FTF + USART TC**：FTF 只表示"字节进了数据寄存器"，还要等 TC 才说明移出完毕；否则控制台的下一个字符会覆盖掉最后那个字节；
   - `fputc()` 也改成**先等 TBE 再写**（原来是先写后等），这是同一处竞态的另一半；
   - 代价：发送一帧期间锁被占 `帧长 × 87 µs`（32 B ≈ 2.8 ms；`raw` 若一帧 500 B ≈ 43 ms），期间敲键盘的回显会延迟这么久，不会丢；
4. **超时保护**：`FTF/TC` 等待都有"按帧长放大"的迭代上限，DMA 异常不会把任务永久挂住，而是计数 `err` 并返回。

### A.4 用法

```
out parsed          # 下行发二进制帧
auto fix            # 跟着定位输出自动发
rate 1              # 但最多 1 Hz
fix                 # 或手动发一次
out raw             # 切 GPS 原报文
auto off            # 停自动发送
gstat               # 看 out/auto/rate、tx 帧数/字节、dropped、err
save                # out/auto/rate 一并存入 Flash
```

> `save` 后 `cli_config_t` 变大（8→12 B），旧的 Flash 记录会因 `size` 不符被判为无效，`load` 返回 `rc=-2` —— 重新 `save` 一次即可。

### A.5 带宽与限流建议

| 场景 | 帧长 | 速率 | 占 115200 的比例 |
|---|---|---|---|
| `parsed` 1 Hz | 32 B | 1 Hz | 0.03 % |
| `parsed` 20 Hz | 32 B | 20 Hz | 0.6 % |
| `raw` GPS 1 Hz（1 条 GPNAV） | ~120 B | 1 Hz | ~1 % |
| `raw` GPS 5 Hz 多条语句 | ~600 B | 5 Hz | ~26 % |

`raw` 的占空比直接跟 GPS 输出走；过载时按"保最新"丢整帧（**不会发半帧**）。

## 附录 B. GPS 上行链路（给模块发命令）

两条路，互不影响：

| 方式 | 语法 | 适用 |
|---|---|---|
| **前缀路由**（默认） | `@<原始命令>`，如 `@log com1 gpnav ontime 5` | 日常：敲一条发一条，其余行仍归 CLI |
| **全量直通** | `bridge on` … `bridge off` | 厂家上位机软件要直连模块、需要连续交互时 |

### B.1 前缀路由

- 前缀字符由配置项 `prefix` 决定，默认 `@`（0x40），`set prefix 0` 关闭；
- `@` 后面的内容**原样**加 CRLF 发给模块，不经 CLI 分词，所以空格/大小写/参数顺序都不受影响；
- 用 `@` 而不是 `$`：Unicore 的配置命令本身不带 `$`（只有输出语句带），用 `$` 会分不清"发配置命令"和"发 NMEA 语句"；也不用 `>`，避免和提示符 `> ` 视觉混淆；
- 既有的 `gps <命令...>` 写法保留，两者并存不冲突（`gps` 会回显 `[gps] -> ...`，`@` 静默转发）。

```
@version                       ← 查模块版本
@log com1 gpnav ontime 5       ← 5 Hz 输出 GPNAV
@unlogall                      ← 关闭全部输出
@saveconfig                    ← 模块侧保存
set prefix #                   ← 换个前缀（想用 # 时）
```

### B.2 透明桥 `bridge on`

**开启后 MCU 就是一个纯数据管道，命令完全不再受理**：

| 方向 | 行为 |
|---|---|
| 下行（GPS → 本口） | `out=raw` 逐字节 DMA 转发 GPS 报文（**不解析、不转换**） |
| 上行（本口 → GPS） | `gps_send_raw()` 把收到的每个字节**原样**转给模块 |
| 命令 | **关闭**：不回显、无提示符、不解析命令行，`[GPS_DATA]` 周期输出也关掉 |

进入时自动强制这些设置，**退出时逐项恢复**（都是运行时改，不写 Flash）：

| 配置项 | 桥内取值 | 原因 |
|---|---|---|
| `out` | `raw` | 只转发原始报文 |
| `auto` | `fix` | 不打开就根本不发数据（`out` 只选内容） |
| `rate` | 20 | 桥不做限流，否则会按默认 1 Hz 丢帧 |
| `verbose` | 0 | 否则 6 行 `[GPS_DATA]` 会混进数据流 |
| `echo` | 0 | 无回显/提示符 —— 命令真的不再受理 |

**两条退出路径**（命令已关闭，所以必须有逃生口）：

1. **`+++`** —— 前面**至少静默 1 秒**之后连续三个 `+` 才退出（Hayes 规范），这三个字节**不转发**给模块。
   "静默 1 秒"这个前提就是保证**正常打字永远不会误退出**：任何其它字节都会立即解除计数；
2. **复位** —— `bridge` 是运行时状态，不进 Flash，重启即回到正常控制台。

> **已删除**早期版本的"静默 10 s 自动退出"：桥里关掉了回显和提示符，操作者看不到倒计时，
> 读一下日志或想一下命令就超过 10 s，结果一输入就被踢出桥 —— 这与"开桥后不再受理命令"矛盾。

```
bridge on
[cli] bridge ON: transparent pipe, GPS <-> this port
[cli] commands are NOT accepted while bridging.
[cli] to leave: send '+++' after >= 1 s of silence, or reset
（此时 GPS 报文原样流出；你敲的字节也原样进模块，不会触发任何命令）
（停手 1 秒以上，再连发三个 +）
+++
[cli] bridge off (+++ escape), console back
>
```

> 注意：桥里的下行是"保最新"语义（不排队）。若 GPS 输出速率超过链路能力，旧帧会被丢弃并计入 `gstat` 的 `dropped(latest)` —— 这是设计取舍，不是故障。

### B.3 实现要点

| 项 | 说明 |
|---|---|
| 前缀路由 | 在 `cli_input()` 的"行结束"分支里判断首字符，命中则调 `gps_send_line(&line[1])` 而不进 `cli_dispatch()` |
| 桥 | `cli_input()` 入口判断 `s_bridge`：先扫 `+++`（命中则退出且不转发），否则把整块字节交给 `gps_send_raw()` 并 `return`（跳过行装配/回显/历史）；进入/退出由 `cli_bridge_exit()` 统一恢复配置 |
| 二进制安全 | `gps_send_raw` 用**带长度**的 `uart_send_buf()`，`0x00` 不会截断 |
| 时间基准 | 静默超时用平台钩子 `uptime_ms`（不是 FreeRTOS tick），所以 `cli.c` 不依赖 RTOS，换平台只要给个毫秒计数 |
| 退出判定 | 全部在 `cli_input()` 的桥分支里：`+++` 需前置静默 ≥ `BRIDGE_PLUS_SILENCE_MS`(1000 ms)，非 `+` 字节立即清零计数；不再有后台超时（`cli_poll()` 已删除） |

### B.4 注意

- 直通期间**敲不了 CLI 命令**（除了等 3 秒静默），需要改配置请先退出；
- 直通期间 `echo`/`verbose`/提示符都不参与，屏幕上是模块的原始回包；
- 有些模块命令要求以 CRLF 结尾，串口助手要设置成"回车换行"；
- `prefix` 会随 `save` 一起进 Flash；`bridge` **不会**（避免板子带着"控制台不可达"启动）；
- 桥内被改掉的 `out/auto/rate/verbose/echo` 也不会写 Flash：退出时恢复成进入前的值，Flash 里的仍是 `save` 时的值。
