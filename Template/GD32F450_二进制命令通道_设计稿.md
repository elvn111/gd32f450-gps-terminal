## 1. 帧格式（核心）

```
+--------+--------+--------+--------+----------------+--------+--------+
| 帧头   | 命令码 | 功能码 | 长度   | 数据内容       | CRC16  | 帧尾   |
| 2 B    | 1 B    | 1 B    | 2 B    | N B            | 2 B    | 2 B    |
| A6 6A  | CMD    | FUNC   | N      | DATA[0..N-1]   | 低字节在前 | B7 7B  |
+--------+--------+--------+--------+----------------+--------+--------+
帧总长 = 2 + 1 + 1 + 2 + N + 2 + 2 = 10 + N 字节
```

| 段 | 长度 | 规定 |
|---|---|---|
| 帧头 | 2 B | 固定 `0xA6 0x6A` |
| 命令码 `CMD` | 1 B | **命令集**：数据上报 / 系统控制 / GPS 模块操作 / 事件上报，见表 §3 |
| 功能码 `FUNC` | 1 B | 同一命令集内的具体内容，见表 §3 |
| 长度 `LEN` | 2 B | 数据段有效字节数 `N`，取值 `0…65535`；字节序建议小端（§11 D1） |
| 数据内容 | N B | 可选参数，编码由 `CMD + FUNC` 决定；`N = 0` 即无数据段 |
| 校验 `CRC16` | 2 B | **CRC-16/MODBUS**，范围 = 帧头起、数据段结束止（`6 + N` 字节），结果低字节在前，**不含帧尾** |
| 帧尾 | 2 B | 固定 `0xB7 0x7B` |

### 1.1 CRC-16/MODBUS

多项式 `0x8005`（反射写法 `0xA001`）、初值 `0xFFFF`、输入输出均反射、结果不异或。

| 用途 | 值 |
|---|---|
| 标准校验向量 `"123456789"`（9 字节 ASCII） | `0x4B37` |
| 本稿样例帧实测值 | 见附录 A（逐帧标注） |

```c
/* 参考实现：与附录 A 的样例帧逐字节一致 */
static uint16_t crc16_modbus(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFFU;
    uint16_t i;
    uint8_t  b;

    for (i = 0U; i < len; i++) {
        crc ^= (uint16_t)data[i];
        for (b = 0U; b < 8U; b++) {
            crc = (0U != (crc & 0x0001U)) ? (uint16_t)((crc >> 1) ^ 0xA001U)
                                          : (uint16_t)(crc >> 1);
        }
    }
    return crc;
}
```

### 1.2 定帧规则（重要）

1. **必须用 `LEN` 定帧，不能靠帧尾定位**：数据段里可能出现 `B7 7B`（例如透传的模块文本），
   搜索帧尾会误判。正确顺序：`帧头 → 长度 → 收满 N 字节 → CRC → 再查帧尾`。
2. 帧尾是**附加校验**：CRC 通过但帧尾不符同样丢帧并计数（可发现错位重同步）。
3. 长度非法（超过接收缓冲上限）或与实际收到的字节数不符 → 丢帧、计数、回到帧头搜索。
4. 需支持**跨分片**（半帧分两次到达）与**半帧超时重同步**（建议 100 ms）。

## 2. 字节2 的分区（bit7 分方向）

| 范围 | 用途 | 方向 |
|---|---|---|
| `0x01–0x0F` | **命令码**（命令集） | 你 → 模块 |
| `0x81–0x8F` | **应答**：字节2 = 请求命令码 `\| 0x80`，字节3 = 请求功能码 | 模块 → 你 |
| `0x90–0x9F` | **数据上报** | 模块 → 你 |
| `0xA0–0xAF` | **事件上报** | 模块 → 你 |
| 其它 | 保留 | — |

一句话规则：**bit7 = 0 是你发给模块的命令，bit7 = 1 是模块发给你的**（应答/数据/事件）。
字节3 是功能码（命令集内 0x01 起）或子类（数据/事件类内 0x01 起）。

### 3.1 `0x01` 系统

|---|---|---|---|
| `0x01` | 读版本 | 序号(1) | 状态(1)+序号(1)+`version(4)` |
| `0x02` | 读配置项 | 序号(1)+`item(1)` | 状态(1)+序号(1)+`value(4)` |
| `0x03` | 写配置项 | 序号(1)+`item(1)`+`value(4)` | 状态(1)+序号(1) |
| `0x04` | 保存配置 | 序号(1) | 状态(1)+序号(1) |
| `0x05` | 读回配置 | 序号(1) | 状态(1)+序号(1) |
| `0x06` | 恢复默认（**全部 9 项**配置） | 序号(1)+确认字(2) | 状态(1)+序号(1) |
| `0x07` | 复位 | 序号(1)+确认字(2) | 无（复位） |
| `0x08` | 清计数 | 序号(1) | 状态(1)+序号(1) |
| `0x09` | 读统计 | 序号(1) | 状态(1)+序号(1)+26 B |

| 功能码 | 名称 | 请求数据段 | 应答数据段 |
|---|---|---|---|
| `0x01` | 设置下行 | 序号(1)+`out(1)`+`auto(1)`+`rate(1)` | 状态(1)+序号(1) |
| `0x02` | 立即发一帧 | 序号(1) | 状态(1)+序号(1) |
| `0x03` | 发终端信息帧 | 序号(1) | 状态(1)+序号(1) |
| `0x04` | 读最近定位 | 序号(1) | 状态(1)+序号(1)+24 B |
| `0x05` | 桥模式 | 序号(1)+`on(1)` | 状态(1)+序号(1) |
| `0x06` | **恢复默认发送**（只动 `out`/`auto`/`rate`，等价文本 `send default`） | 序号(1) | 状态(1)+序号(1) |

| 功能码 | 名称 | 请求数据段 | 应答数据段 |

| `0x04` | 工厂复位 | 序号(1)+确认字(2) | 状态(1)+序号(1) |

### 3.4 上行数据（模块 → 你）

| 字节2 | 字节3 | 名称 | 数据段 | N |
|---|---|---|---|---|
| `0x90` | `0x01` | 定位数据 | 帧序号(2) + 24 B 定位量 | 26 |

## 4. 应答约定

1. **字节2 = 请求命令码 `| 0x80`，字节3 = 请求功能码**（例：写配置项 `0x01/0x03` → 应答 `0x81/0x03`），对端据此一眼配对。
2. 应答数据段固定前缀：`状态(1)` + `回带序号(1)`，其后是该命令的数据。
3. 请求数据段第 1 字节**约定为序号**（主机自增 0…255 回绕），用于区分"同一条命令重发"与"两条不同命令"。
4. 终端**不重传**，重发由主机决定；读/写/保存类命令幂等，重发安全。

## 5. 状态码与配置项 ID

| 状态码 | 名称 | 含义 |
|---|---|---|
| `0x00` | `OK` | 执行成功 |
| `0x01` | `UNKNOWN_FUNC` | 功能码不支持（含未知命令码） |
| `0x02` | `BAD_PARAM` | 参数越界、长度不符、文本超长 |
| `0x03` | `BUSY` | 上一条命令未执行完 |
| `0x04` | `UNSUPPORTED` | 该硬件/平台未实现 |
| `0x06` | `NEED_CONFIRM` | 危险命令缺确认字 |
| `0x07` | `WRITE_PROTECTED` | 写保护开启，拒绝写类命令 |
| `0x08` | `NOT_READY` | 数据未就绪（如暂无定位） |
| `0x09` | `CMD_CHANNEL_OFF` | 命令通道未开启 |

`0x05` 预留给帧级校验错。**CRC 或长度错的帧建议静默丢弃并计数**、不回应答，避免坏帧引发应答风暴（§11 D12）。

| 配置项 ID | 名称 | 取值 |
|---|---|---|
| `0x01` | `mode` | 0/1 |
| `0x02` | `echo` | 0/1 |
| `0x03` | `verbose` | 0/1 |
| `0x04` | `sat_min` | 0…40 |
| `0x05` | `gps_baud` | 9600…921600 |
| `0x06` | `out` | 0/1/2 |
| `0x07` | `auto` | 0/1/2 |
| `0x08` | `rate` | 1…20 |
| `0x09` | `prefix` | 0…126 |

配置值统一按 **u32 小端**（§11 D11）。

## 6. 与现有链路的关系

**已按方案甲迁移完成**：定位数据、终端信息改用 `0x01/0x01`、`0x01/0x02`，
链路只剩一种帧格式（`A6 6A … B7 7B`）、一种 CRC（MODBUS）、一个解析状态机。

迁移内容：`gps_link.h/.c` 的帧头/帧尾/CRC/长度上限与组帧函数；协议规范 §2/§3/§9/§10 与附录 A/B/C/E/F；
6 个样例帧按新格式重算；PC 校验脚本改为 MODBUS。**载荷字段布局未变**，仅数据段前多了 2 字节帧序号。

## 7. 与文本控制台、桥模式的共存

| 机制 | 处理 |
|---|---|
| 文本控制台 | 完全保留。分流判据：`0xA6`/`0xB7` 都不是可打印 ASCII，**文本行里不可能出现** → "帧 vs 文本"无歧义 |
| 桥模式 `bridge on` | 二进制通道**不生效**，字节全部透明转发给 K922；退出仍用静默 ≥1 s 的 `+++` |
| 回显 `echo` | 开启命令通道时自动置 0（§11 D10），避免提示符混入应答解析 |
| `[GPS_DATA]` 报告 | 不受影响；对端场景建议文本侧 `verbose 0` |

```
收到字节：
  桥模式 → 全部转给 USART5（透明）
  否则：
    0xA6 → 等 0x6A → 读 LEN → 判范围 → 收满 N → CRC → 帧尾 → 按 CMD/FUNC 分派
    其它 → 交给文本行缓冲（现有 CLI 路径）
  半帧超时 100 ms → 复位状态机并计数
```

## 8. 时序与语义

| 项 | 规定 |
|---|---|
| 并发 | 同一时刻只处理一条命令；未完成时新命令回 `0x03` |
| 执行上下文 | 与文本命令同任务、同输出锁 → 与 6 行报告、上报帧互不交叉 |
| 重传 | 终端不重传；主机可重发（幂等） |
| 超时（主机） | 普通命令 200 ms；保存配置 2 s；复位不等待应答，1 s 后重新读版本 |
| 命令期间输入 | 由 2048 B 环形缓冲吸收，不丢（现有实现已具备） |
| 上报语义 | 仍是"保最新"：旧值丢弃并计数，靠帧序号跳变体现 |

**与上报数据流的语义差异**（最易混）：上报 = 保最新、可丢、受速率限制；命令/应答 = 不丢、串行、每条必有应答。

**Q7 恢复默认发送请求（`0x02 / 0x06`）**（总长 11，CRC=0x483D）

```
A6 6A 02 06 01 00 01 3D 48 B7 7B
```

数据段只有序号 1；等价文本命令 `send default`（`out=parsed`、`auto=fix`、`rate=20`，不动其余 6 项）。
对应答：

```
A6 6A 82 06 02 00 00 01 56 05 B7 7B
```

`0x82/0x06`，数据段 = 状态 `0x00`(OK) + 回带序号 1。

**G1 GPS 命令透传（`0x03 / 0x01`）**（总长 34，CRC=0x8DB3）

```
A6 6A 03 01 18 00 0D 6C 6F 67 20 63 6F 6D 31 20
67 70 6E 61 76 20 6F 6E 74 69 6D 65 20 31 B3 8D
B7 7B
```
数据段 = 序号 + 文本，自动补 CRLF。

**G2 GPS 硬复位（`0x03 / 0x02`）**（总长 11，CRC=0xBC41）

```
A6 6A 03 02 01 00 0E 41 BC B7 7B
```
数据段 = 序号。

**E1 错误应答：未知功能码（`0x81 / 0x7F`）**（总长 12，CRC=0xA84B）

```
A6 6A 81 7F 02 00 01 0F 4B A8 B7 7B
```
数据段 = 状态 `0x01`(UNKNOWN_FUNC) + 回带序号 15。

**E2 事件上报：定位丢失（`0xA0 / 0x01`）**（总长 16，CRC=0x8B22）

```
A6 6A A0 01 06 00 14 05 A0 BB 0D 00 22 8B B7 7B
```
数据段 = 帧序号 1300 + 上电毫秒 900000。

## 附录 B：与文本命令的对照

| 文本命令 | 二进制 | 备注 |
|---|---|---|
| `ver` / `status` | `0x01/0x01`、`0x01/0x09` | 文本更详细，二进制只给机器需要的字段 |
| `get` / `set` | `0x01/0x02`、`0x01/0x03` | 用 §5 的配置项 ID |
| `out` / `auto` / `rate` | `0x02/0x01` | 一条命令设完三项 |
| `send default` | `0x02/0x06` | 只把下行三项恢复默认（= `out=parsed`、`auto=fix`、`rate=20`） |
| `fix` | `0x02/0x02` | — |
| `info` | `0x02/0x03`（要一帧）/ `0x90/0x02`（收到的那一帧） | — |
| `gps <命令>` / `@命令` | `0x03/0x01` | 文本参数原样透传 |
| `gps hwreset` / `gps init` / `gps freset` | `0x03/0x02`、`0x03/0x03`、`0x03/0x04` | 工厂复位需确认字 |
| `bridge on\|off` | `0x02/0x05` | 退出桥仍可用 `+++` |
| `save` / `load` / `default` / `clr` / `reboot` | `0x01/0x04`、`0x01/0x05`、`0x01/0x06`、`0x01/0x08`、`0x01/0x07` | 恢复默认与复位需确认字 |
| `tasks` / `dma` / `mode` | 无对应 | 纯诊断/本地操作，保留文本入口 |
