# 1 概述

本章规定定位终端与主机之间的通信接口、帧格式与命令集。终端与主机之间使用一路异步串口连接，终端以下行（主机→终端）命令为从，以上行（终端→主机）数据上报为主，二者共用同一条帧格式。

## 1.1 通信接口

| 项目 | 规定 |
|---|---|
| 物理接口 | 3.3 V TTL 异步串口（USART0），终端为 DCE 侧，主机为 DTE 侧 |
| 波特率 | 115200 bit/s（默认，固定于当前固件版本） |
| 数据格式 | 8 数据位、无校验、1 停止位（8-N-1），无流控 |
| 字节序 | 除校验码外，**所有多字节数值高字节在前（大端，高字节先发）**，包括数据长度与数据段各字段，与 TXP 系列雷达协议一致；CRC-16/MODBUS 结果低字节在前 |
| 工作方式 | 全双工；终端不主动重传，重传由主机决定 |
| 同一链路上的其它内容 | 除帧之外，终端上电横幅与工程用文本控制台也走本链路（见 3.7）。帧头 `0xA6`、帧尾 `0xB7` 均非可打印 ASCII，文本行中不可能出现，二者不冲突 |

## 1.2 帧格式

表 1 帧格式

| 名称 | 空间 | 含义 |
|---|---|---|
| 帧头 | 2 字节 | 用于检测帧接收的起始位置，固定为 `0xA6 0x6A` |
| 命令码 | 1 字节 | 用于指定命令集。**bit7 分方向**：`0x01~0x0F` 为主机下发的命令码；`0x81~0x8F` 为终端应答（= 命令码 `\| 0x80`）；`0x90~0x9F` 为终端数据上报；`0xA0~0xAF` 为终端事件上报 |
| 功能码 | 1 字节 | 用于指定对应命令集内的特定功能，命令集内自 `0x01` 起编号 |
| 数据长度 | 2 字节 | 用于确定当前帧数据域的数据长度 N（高字节先发），取值范围 0~65535 |
| 数据内容 | N 字节 | 数据域内容。N 可为 0，表示无数据域。N 的取值由命令码与功能码决定 |
| 校验码 | 2 字节 | CRC-16/MODBUS，用于校验从帧头开始到数据域结束的连续部分。**校验结果低字节先发送** |
| 帧尾 | 2 字节 | 帧尾标志，固定为 `0xB7 0x7B` |

一个命令集包含多个功能码，命令码、功能码与数据内容均属于数据载荷。终端的请求报文与应答报文命令码按 bit7 区分，可通过命令码直接配对。

表 2 帧格式数据包发送格式

| 帧头 | 命令码 | 功能码 | 数据长度 | 数据内容 | 校验码 | 帧尾 |
|---|---|---|---|---|---|---|
| 字节 0~1 | 字节 2 | 字节 3 | 字节 4~5 | 字节 6~(N+6) | 字节 N+7~N+8 | 字节 N+9~N+10 |
| A6 6A | 命令码 | 功能码 | 数据长度 N | 数据域 | 校验码 | B7 7B |

帧头：2 个字节帧头 —— `0xA6 0x6A`；

命令码：1 个字节 —— 区分命令集与方向，见 1.3；

功能码：1 个字节 —— 同一命令集内区分具体功能；

数据长度：2 个字节，N 有效值为 0~65535（高字节先发）；

数据内容：N 个字节 —— 可选参数，根据具体命令而定；

校验码：2 个字节 —— CRC-16/MODBUS，用于校验从帧头开始到数据域结束的连续部分（低字节在前），不含帧尾；

帧尾：2 个字节帧尾 —— `0xB7 0x7B`。

帧总长 = 2 + 1 + 1 + 2 + N + 2 + 2 = **10 + N 字节**。定位数据帧（`0x90/0x01`）36 字节，终端信息帧（`0x90/0x02`）44 字节。

### 2.1.1 定位数据上报

终端每解析出一条有效定位语句即刷新一份最新定位值，按配置的触发方式与速率上限上报。数据段前 2 字节为帧序号，其后 24 字节为定位量。

定位数据上报数据载荷如下表所示：

表 9 定位数据上报数据载荷

| 命令码 | 功能码 | 数据长度 | 数据内容 |
|---|---|---|---|
| 字节 2 | 字节 3 | 字节 4~5 | 字节 6~(N+6) |
| 0x90 | 0x01 | 数据长度 N | 数据内容 |

数据长度 N：固定 26 字节（帧序号 2 字节 + 定位量 24 字节）。

数据内容：依次列出如下：

表 10 定位数据上报数据内容

| 数据内容 | 所占空间 | 取值范围 | 定标 / 单位 | 备注 |
|---|---|---|---|---|
| 帧序号 | uint16 | 0~65535 | — | 随帧递增，见 3.3 |
| 纬度 | int32 | -900000000 ~ 900000000 | 1e-7 度 | 负值为南纬，二进制补码 |
| 经度 | int32 | -1800000000 ~ 1800000000 | 1e-7 度 | 负值为西经，二进制补码 |
| 高度 | int32 | -20000000 ~ 20000000 | 毫米 | 基准面随来源语句不同，见下注 2 |
| 航向角 | uint16 | 0 ~ 36000 | 0.01 度 | 36000 等效 0 度 |
| 基线长度 | uint32 | 0 ~ 20000000 | 毫米 | 双天线定向基线 |
| 卫星数 | uint8 | 0 ~ 255 | 颗 | 参与解算的卫星数 |
| 状态位 | uint8 | — | — | 逐位定义见 3.4 |
| 时间戳 | uint32 | 0 ~ 4294967295 | 毫秒 | 终端上电毫秒数，见 3.3 |

注 1：所有数值字段均为高字节先发（大端）；校验码低字节在前。

注 2：高度基准面随数据来源语句不同——来自 `$GPYBM` 时为椭球高，来自 `$GPNAV` 时为海拔高；主机**应**用状态位的来源位决定如何解释。

注 3：终端对高度做量程检查，超出 ±20000 米的值按 0 处理并置状态位为无效，不会出现溢出值。

通信示例 1（已定位，`$GPYBM` 来源，状态位有效）：

```

      00 00 30 39 22 11 00 00 04 D2 12 03 00 0B 82 91
      7E ED B7 7B
```

| 字段 | 值 |
|---|---|
| 帧头 / 命令码 / 功能码 | `A6 6A` / 0x90（数据上报）/ 0x01（定位数据） |
| 数据长度 N / 帧总长 | 26 / 36 字节 |
| 帧序号 | 1204 |
| 纬度 / 经度 | 30.1234567 / 120.7654321 |
| 高度 / 航向角 / 基线 | 12.345 m / 87.21° / 1.234 m |
| 卫星数 / 状态位 | 18 / 0x03（有效，来源 `$GPYBM`） |
| 时间戳 | 754321 ms |
| 校验码 | 0xED7E（线上低字节在前） |

通信示例 2（尚未定位：模块无卫星，数值全 0，状态位无效）：

```
      A6 6A 90 01 00 1A 04 B6 00 00 00 00 00 00 00 00
      00 00 00 00 00 00 00 00 00 00 00 00 00 0B 82 92
      E1 41 B7 7B
```

帧序号 1206，全部数值为 0，卫星数 0，状态位 0x00（无效），时间戳 754322 ms，校验码 0x41E1。

> 状态位无效的帧**照常上报**。主机**不得**因为数值为 0 就丢弃整帧，**应**按状态位决定是否采纳数值，并可用无效帧的持续到达判断链路与终端是否在线。

### 2.1.2 终端信息上报

终端信息上报用作链路心跳与上电自检：终端状态、版本、收发计数与当前下行配置都在一帧内给出。主机可据此判断终端是否在线、链路是否丢帧、终端当前按什么配置上报。

两种触发条件：

1. 主机显式索取（`0x02/0x03`，或文本控制台命令 `info`）；
2. **链路保活**：终端连续 1 秒内没有任何帧发出时，自动补发一帧终端信息帧。定位数据正常上报期间不会补发，不增加额外流量。

因此主机在任何时刻接入链路，最长 1 秒内必能收到一帧，模块无定位或模块静默时同样成立。

| 0x90 | 0x02 | 数据长度 N | 数据内容 |

# 3 通信约定

## 3.1 应答约定

1. 应答帧的命令码 = 请求命令码 `| 0x80`，功能码 = 请求功能码。例：设置配置项 `0x01/0x03` 的应答为 `0x81/0x03`。
2. 应答数据段固定前缀为 `状态(1)` + `回带序号(1)`，其后是该命令的数据。
3. 请求数据段第 1 字节为序号，由主机自增（0~255 回绕），终端原样回带，用于把应答与请求配对、区分重发。
4. 终端**不重传**：命令丢失或应答丢失由主机重发。读、写、保存类命令幂等，重发安全。
5. CRC 或长度错误的帧终端**静默丢弃并计数**，不回应答，避免坏帧引发应答风暴。
6. 主机等待应答的超时建议值：普通命令 200 ms，保存配置 2 s，系统重启不等待（1 s 后重新读版本）。

表 57 状态码

| 0x00 | OK | 执行成功 |
| 0x01 | UNKNOWN_FUNC | 命令码或功能码不支持 |
| 0x02 | BAD_PARAM | 参数越界、长度不符、文本超长 |

## 3.3 帧序号与时间戳语义

1. 帧序号位于数据段第 0、1 字节（高字节先发），数据上报帧与事件上报帧共用同一个计数器。
2. 每成功发出一帧加 1，取值 0~65535，回绕后继续；**未成功发出的帧不消耗序号**。
3. 主机**应**用序号差值统计丢帧：差值 = 被“保最新”策略覆盖的帧 + 线路错误丢掉的帧。
4. 同一序号重复出现属异常，主机**应**计数并丢弃后到者。
5. 时间戳为终端上电以来的毫秒数，在生成该帧时采样，不是绝对时间；主机**不得**当作 UTC 使用，比较时按无符号差值处理（约 49.7 天回绕一次）。

## 3.4 状态位定义

表 59 状态位定义

| 位 | 名称 | 含义 |
|---|---|---|
| bit0 | VALID | 1 = 本帧数值有效 |
| bit1 | SRC_GPYBM | 1 = 数据来自 `$GPYBM`；0 = 来自 `$GPNAV` |
| bit2~bit7 | 保留 | 终端置 0，主机**应**忽略 |

`VALID = 1` 的判定条件（全部满足才置位）：语句通过校验和与最小字段数检查；被使用字段非空且为数字；数值在物理范围内（纬度 ±90 度、经度 ±180 度、航向 0~360 度）；定位解状态可用；定向解可用；参与解算卫星数达到配置的最少星数（`sat_min`）。

`VALID` 已包含星数门槛，主机**不应**再用卫星数自行判一遍。`VALID = 0` 的帧照常上报，主机**应**用 `VALID` 决定是否采纳数值，而不是丢弃整帧。

## 3.5 下行发送语义

1. **保最新**：终端不排队、不缓存历史值。同一时刻只保留最新一份定位值，触发时把最新值组帧发出；来不及发出的中间值被覆盖并计入“覆盖丢弃数”。因此主机看到的帧率可能低于模块输出速率，这是设计行为，不是丢帧故障。
2. 触发方式（配置项 `auto`）：`0` 手动（只由 `0x02/0x02` 触发）、`1` 新值触发（每解析出一份新定位即发一帧）、`2` 定时（按 `rate` 周期发最新值）。
3. 速率上限（配置项 `rate`）为 1~20 Hz，对以上三种方式都生效。
4. **保活**：连续 1 秒内没有任何帧发出时，终端自动补发一帧终端信息帧（2.1.2）。所以无论模块是否有定位、链路是否空闲，主机最长 1 秒内必能收到帧。
5. 下行内容（配置项 `out`）为 `1`（原报文）时，终端把模块原始语句按帧转发，帧的数据段即语句字节（含 CR LF），命令码 `0x90`、功能码 `0x01`。该模式用于过程记录与二次解析，帧长随语句长度变化。
6. 终端上电后约 300 ms 开始配置定位模块，随后以 250 ms 间隔逐条下发模块配置命令；若模块 10 秒内没有任何语句返回，终端每 5 秒补发其中的日志命令，直到模块恢复输出。因此上电到首帧的时间通常在 1~3 秒，模块冷启动（如长时间断电后）可能更久。主机在此期间**不应**判定链路故障。

## 3.6 校验码

参数：多项式 `0x8005`（反射写法 `0xA001`），初值 `0xFFFF`，输入输出均反射，结果不异或，即 **CRC-16/MODBUS**。

计算范围：帧头起、数据段结束止，共 `6 + N` 个字节；结果**低字节在前**，位于帧尾之前，**不含帧尾**。

标准校验值：`"123456789"`（9 个 ASCII 字节）→ `0x4B37`。

参考实现见附录 A。

## 3.7 定帧规则与异常处理

1. **必须用数据长度 N 定帧，不能搜索帧尾**：数据段中可能出现 `B7 7B`（例如透传的模块文本）。正确的接收顺序是：找帧头 → 取长度 → 收满 N 个字节 → 校验 CRC → 再查帧尾。
2. 帧尾是附加校验：CRC 通过但帧尾不符，同样丢帧并计数。
3. N 与实际收到的字节数不符，或超过接收缓冲上限（终端侧为 256 字节）时，丢帧、计数并回到帧头搜索状态。
4. 需支持半帧分两次到达；半帧超时（建议 100 ms）后复位接收状态机并计数。
5. 同一链路上还有终端上电横幅与工程用文本控制台输出。帧头 `0xA6`、帧尾 `0xB7` 均非可打印 ASCII，文本行中不可能出现，因此“帧”与“文本”无歧义：主机按帧头字节匹配，未匹配的字节按文本丢弃。

表 60 文本控制台与二进制帧的分流

| 收到字节 | 终端行为 |
|---|---|
| 帧头 `A6 6A` 且长度与 CRC 合法 | 按命令帧处理，并在需要时回应答 |
| 其它字节 | 按文本行处理（控制台命令），不产生二进制应答 |

# 附录 A CRC-16/MODBUS 参考实现

```c
/* CRC-16/MODBUS：多项式 0x8005(反射 0xA001)、初值 0xFFFF、输入输出反射、结果不异或。
 * 计算范围：帧头起、数据段结束止，共 6+N 字节；结果低字节在前写入帧中。 */
unsigned short crc16_modbus(const unsigned char *buf, unsigned int len)
{
    unsigned short crc = 0xFFFF;
    unsigned int   i;
    unsigned char  bit;

    for (i = 0; i < len; i++) {
        crc ^= (unsigned short)buf[i];
        for (bit = 0; bit < 8; bit++) {
            if (0 != (crc & 1)) {
                crc = (unsigned short)((crc >> 1) ^ 0xA001);
            } else {
                crc = (unsigned short)(crc >> 1);
            }
        }
    }
    return crc;
}
```

# 附录 C 接入检查清单

主机侧接入前逐项确认：

1. 串口参数为 115200-8-N-1，无流控；多字节字段按高字节先发解析（校验码低字节在前）。
2. 接收按“帧头 → 长度 → 收满 N → CRC → 帧尾”的顺序定帧，不依赖帧尾搜索。
3. 上电后 1~3 秒内应收到首帧；未收到时先用 `0x02/0x03`（或文本 `info`）主动索取一帧。
4. 用状态位的 `VALID` 决定是否采纳定位数值，不用数值是否为 0 判断。
5. 用帧序号差值统计丢帧，识别“保最新”造成的正常覆盖。
6. 命令超时按 3.1 设定；对未实现功能（表 5 中完成状态为“×”）按 `0x04 UNSUPPORTED` 处理。
7. 破坏性命令（恢复默认配置、系统重启、模块工厂复位）必须带确认字 `0x5AA5`。
