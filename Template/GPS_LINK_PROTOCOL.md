# GPS 下行链路协议（GD32F450 → 第二颗 MCU）

> 版本：v1.0 · 对应固件：CLI v1.2.0 / `gps_link.c` v1.0
> 物理层：**USART0，115200-8-N-1，无流控**（与 MCU 控制台**共用同一根线**）
> 目标读者：**接收端（第二颗 MCU）固件开发者**

---

## 1. 两种下行内容（由发送端 `out` 决定，接收端需能同时识别）

| `out` | 内容 | 接收端如何界定帧 |
|---|---|---|
| `raw` | **GPS 原始报文**，字节级透传（NMEA `$.....`） | 按 `\n` 分行；`$` 开头、`*hh` 结尾自带异或校验 |
| `parsed` | **本协议二进制帧**（下述格式） | 按 `SOF + LEN + CRC16` 解析 |
| `off` | 不发任何下行数据 | —— |

`raw` 与 `parsed` 是**同一条线上的两种内容**，靠字节特征即可区分：`0xA5 0x5A` 开头 = 二进制帧；`$` 开头 = 原文。建议接收端做成"嗅探式"状态机（见 §8）。

---

## 2. 二进制帧格式（`out=parsed`）

```
+--------+--------+--------+--------+--------+-----------+--------+--------+
| SOF0   | SOF1   | LEN    | TYPE   | SEQ    | PAYLOAD   | CRC16 (little)  |
| 0xA5   | 0x5A   | 1 B    | 1 B    | 2 B LE | LEN-3 B   | 2 B LE          |
+--------+--------+--------+--------+--------+-----------+--------+--------+
```

| 字段 | 说明 |
|---|---|
| `SOF` | 固定 `0xA5 0x5A`，帧同步头 |
| `LEN` | **TYPE + SEQ + PAYLOAD 的字节数**（不含 SOF/LEN/CRC）。当前 `TYPE=1` 时恒为 **27** |
| `TYPE` | `0x01` = 解析后的定位（本文件唯一类型，预留扩展） |
| `SEQ` | uint16 小端，**每发一帧 +1**，回绕到 0 继续。接收端用它发现丢帧 |
| `PAYLOAD` | 见 §3，`TYPE=1` 时 24 B |
| `CRC16` | uint16 小端，**CRC-16/CCITT-FALSE**，计算范围 = `LEN` 个字节（即 `TYPE` 起到 `PAYLOAD` 结束） |

**帧总长 = 2 + 1 + LEN + 2 = 32 字节**（当前版本，固定）。

---

## 3. PAYLOAD 字段（24 B，全部小端）

| 偏移 | 字段 | 类型 | 定标 / 单位 | 范围 |
|---|---|---|---|---|
| +0 | `lat_e7` | int32 | 纬度 × **1e7** | ±90×1e7 |
| +4 | `lon_e7` | int32 | 经度 × **1e7** | ±180×1e7 |
| +8 | `h_mm` | int32 | 椭球高，**mm** | ±2.1×10⁹ mm |
| +12 | `head_cd` | uint16 | 航向 × **0.01°** | 0..35999（359.99°） |
| +14 | `base_mm` | uint32 | 基线长度，**mm** | 0..4.29×10⁹ mm |
| +18 | `sat` | uint8 | 参与解算卫星数 | 0..255 |
| +19 | `flag` | uint8 | 见下 | 位域 |
| +20 | `t_ms` | uint32 | **发送端上电以来的毫秒数**（该帧生成时刻） | 0..2³²-1 |

**实际字节偏移（含帧头）**：`lat_e7` 在帧内偏移 **6**，`lon_e7` = 10，`h_mm` = 14，`head_cd` = 18，`base_mm` = 20，`sat` = 24，`flag` = 25，`t_ms` = 26，CRC 在 **30..31**。

### `flag` 位定义

| 位 | 名称 | 含义 |
|---|---|---|
| bit0 | `VALID` | 1 = 卫星数 ≥ 发送端 `sat_min`（定位可信） |
| bit1 | `SRC_GPYBM` | 0 = 数据来自 `$GPNAV`；1 = 来自 `$GPYBM` |
| bit2..7 | 保留 | 当前恒为 0，接收端应忽略 |

> 注意：**接收端不要假设 `flag` 保留位为 0 就代表版本一致**，只按位解释自己认识的位。
> 也不要依赖 `t_ms` 做绝对时间，它只是发送端 uptime，用于抖动/丢帧分析。

## 4. CRC-16/CCITT-FALSE 参考实现

参数：`poly=0x1021, init=0xFFFF, refin=false, refout=false, xorout=0x0000`。

```c
/* 与发送端 gps_link.c 完全一致；输入 data 指向 TYPE 字节，len = LEN */
static uint16_t crc16_ccitt_false(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFFU;
    uint16_t i;
    uint8_t  b;

    for (i = 0U; i < len; i++) {
        crc ^= (uint16_t)((uint16_t)data[i] << 8);
        for (b = 0U; b < 8U; b++) {
            crc = (0u != (crc & 0x8000U)) ? (uint16_t)((uint16_t)(crc << 1) ^ 0x1021U)
                                          : (uint16_t)(crc << 1);
        }
    }
    return crc;
}
```

**校验标准值**（可用于自测）：`"123456789"` 的 CRC-16/CCITT-FALSE = `0x29B1`。
本协议某帧的实测值见 §5。

## 5. 实际帧样例（可直接用于接收端自测）

### 5.1 有效定位（GPNAV 来源，flag=0x03）

原始值：`lat=30.1234567°, lon=120.7654321°, h=12.345 m, head=87.21°, base=1.234 m, sat=18, t=12345 ms, seq=1`

```
A5 5A 1B 01 01 00 87 79 F4 11 B1 57 FB 47 39 30 00 00
11 22 D2 04 00 00 12 03 39 30 00 00 0A 13
```

- `LEN = 0x1B = 27`，`TYPE = 01`，`SEQ = 01 00` → 1
- `lat_e7 = 301234567`、`lon_e7 = 1207654321`、`h_mm = 12345`、`head_cd = 8721`、`base_mm = 1234`、`sat = 18`、`flag = 0x03`、`t_ms = 12345`
- `CRC16 = 0x130A`（线上字节 `0A 13`）

### 5.2 尚未定位（GPYBM 来源，flag=0x02）

```
A5 5A 1B 01 02 00 00 00 00 00 00 00 00 00 00 00 00 00 00
00 00 00 00 00 00 03 02 20 4E 00 00 57 9E
```
`CRC16 = 0x9E57`（线上 `57 9E`），`sat = 3`，`flag = 0x02`（无 VALID 位）。

### 5.3 南半球 + 航向 359.99° + SEQ 回绕

```
A5 5A 1B 01 FF FF 00 08 D0 EB 48 B5 20 5A 85 EA FF FF
9F 8C 00 00 00 00 19 01 3F 42 0F 00 9D E0
```
`lat_e7 = -338688000`（-33.8688°）、`lon_e7 = 1512093000`、`h_mm = -5499`、`head_cd = 35999`、`base_mm = 0`、`sat = 25`、`flag = 0x01`、`SEQ = 0xFFFF`、`CRC16 = 0xE09D`。

> 复数（负值）用**二进制补码**表示：`lat_e7` / `h_mm` 为 int32，`base_mm` 为 uint32（不为负）。

## 6. "保最新"语义（接收端必须理解）

发送端**不排队、不带 ACK、不带重传、不做流控**：

1. 发送端只保留**最新一份**数据（原始报文一份 / 解析结果一份）；
2. 若上一份**还没发出去**就被新数据覆盖 → 记为一次 `dropped(latest)`（`gstat` 可见），**旧的自然丢弃**；
3. 因此接收端会看到：
   - **`SEQ` 跳变** = 中间有帧被"保最新"策略丢掉（或线路错误后重同步）；
   - **`t_ms` 跳变** = 数据更新间隔（可用于判断 GPS 是否停更）；
   - **永远不会收到的**：积压的历史帧。这是设计意图，不是故障。

**接收端建议**：
- 只校验 `SOF/LEN/CRC`，通过即采纳，不做等待/重传确认；
- 用 `SEQ` 差值统计丢帧率，用 `t_ms` 统计数据年龄（`now_local - t_ms` 需折算，因为时钟不同源）；
- 定位无效（`flag.bit0 = 0`）时，可选择丢弃或按"最后有效值 + 超时"策略使用。

## 7. 触发方式与速率（发送端配置）

| 配置 | 取值 | 说明 |
|---|---|---|
| `out` | `off` / `raw` / `parsed` | 下行内容，默认 `off` |
| `auto` | `off` / `fix` / `tick` | `off`：只在敲 `fix` 时发一次；`fix`：每来一帧新数据就发（受 `rate` 限流）；`tick`：每 `1/rate` 秒发一次最新值（心跳，即使没更新） |
| `rate` | 1..20 Hz | 限流上限；`tick` 模式下就是发送周期 |

**带宽参考**（接收端可用于评估任务负载）：

| 场景 | 帧长 | 速率 | 占用（115200 ≈ 11.5 KB/s） |
|---|---|---|---|
| `parsed` + 1 Hz | 32 B | 1 Hz | 0.03 % |
| `parsed` + 20 Hz | 32 B | 20 Hz | 0.6 % |
| `raw` + GPS 1 Hz（1 条 GPNAV ≈ 120 B） | ~120 B | 1 Hz | ~1 % |
| `raw` + GPS 5 Hz 多条语句 | ~600 B/帧 | 5 Hz | ~26 % |

> `raw` 模式下占空比直接跟 GPS 输出走；**接收端不做流控**，发送端按"保最新"处理不过来就丢整帧（绝不会发半帧——每帧都是一次原子 DMA 发送）。

## 8. 接收端参考实现（状态机 + CRC 校验）

```c
/* 在 USART 接收中断（或 DMA + 空闲中断）里逐字节喂入即可 */
typedef struct {
    uint8_t  buf[64];
    uint16_t idx;
    uint16_t expect;          /* 一帧总长 = 2 + 1 + LEN + 2 */
} gl_rx_t;

static void gl_feed(gl_rx_t *rx, uint8_t b)
{
    if (0U == rx->idx) {
        if (0xA5U == b) { rx->buf[rx->idx++] = b; }
        return;                                  /* 其它字节直接丢弃 */
    }
    if (1U == rx->idx) {
        if (0x5AU == b) { rx->buf[rx->idx++] = b; }
        else            { rx->idx = 0U; }         /* 假头，重同步 */
        return;
    }
    if (rx->idx >= sizeof(rx->buf)) { rx->idx = 0U; return; }
    rx->buf[rx->idx++] = b;

    if (2U == rx->idx) {                          /* LEN 到手，算总长 */
        if (0U == b || b > 40U) { rx->idx = 0U; return; }
        rx->expect = (uint16_t)(2U + 1U + b + 2U);
    }
    if (rx->idx == rx->expect) {
        const uint8_t *f = rx->buf;
        uint8_t  len  = f[2];
        uint16_t crc  = crc16_ccitt_false(&f[3], len);
        uint16_t got  = (uint16_t)(f[3 + len] | ((uint16_t)f[3 + len + 1] << 8));
        if (crc == got) {
            /* 解析 f[3] = TYPE, f[4..5] = SEQ, f[6..] = PAYLOAD */
            /* ... 交给应用层 ... */
        }
        rx->idx = 0U;                             /* 无论成败都重同步 */
    }
}
```

**要点**
- 只在 `idx==0` 时等待 `0xA5`，`0xA5` 后面的非 `0x5A` 直接归零重同步（原始 NMEA 数据里也可能出现 `0xA5`，所以必须两字节判头）；
- `LEN` 要先做范围检查（本协议 ≤ 40）再算总长，防野长度把缓冲写越界；
- 校验失败**直接丢整帧并重同步**，不要尝试修补；
- 需要同时吃 `raw` 文本时，在 `idx==0` 分支里加一条：收到 `$` 且未收到 `0xA5` → 走"按行收文本"的另一个状态。

## 9. 联调步骤（发送端命令）

```
gstat                     ← 看 out/auto/rate 与收发计数
out parsed                ← 选择二进制帧
auto fix                  ← 每来一帧定位就发（跟着 GPS 输出走）
rate 1                    ← 但最多 1 Hz（保最新）
fix                       ← 或：手动发一次（auto off 时用）
out raw                   ← 切原始报文透传（接收端按行解析）
auto off                  ← 停止自动发送
save                      ← 把 out/auto/rate 存进 Flash，掉电保留
```

**验收标准**：接收端用 §5 的样例帧自测通过 → 现场 `out parsed; auto fix; rate 1` 运行 30 分钟，`gstat` 的 `dropped(latest)` 与接收端统计的 `SEQ` 跳变次数应基本一致（差值 = 校验失败帧数）。
