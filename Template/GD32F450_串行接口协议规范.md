## 1. 系统组成

```
        ┌─────────────────────────── GD32F450 终端 ───────────────────────────┐
        │                                                                     │
外部设备 │  USART0  ┌──────────────┐   USART5   ┌───────────────┐              │
◄────────┼─────────►│ 命令解释器   │◄──────────►│  采集 / 解析  │◄────────────►│ K922 定位模块
  双向  │  115200  │ 下行链路     │   115200   │  下行组帧     │   双向 115200│
        │          └──────────────┘            └───────────────┘              │
        └─────────────────────────────────────────────────────────────────────┘
```

| 接口 | 对端 | 方向 | 串口参数 | 帧界定方式 |
|---|---|---|---|---|
| USART0 | 外部主机或第二颗 MCU | 双向 | 115200-8-N-1，无流控，3.3 V TTL | 行（CR / LF / CRLF）或帧头 `A5 5A` |
| USART5 | K922 定位模块 | 双向 | 115200-8-N-1，无流控（可配置 9600…921600） | NMEA 语句，`$` 起、`*hh` 校验、CRLF 止 |

**电气与接口约定**

1. 两个串口均为 3.3 V TTL，**不得**直接接入 RS-232 电平。
2. 未使用硬件流控（RTS/CTS 未连接），发送端不做流控等待。
3. USART0 是全双工：同一时刻可以双向收发；外部设备**应**按"发送与接收互不阻塞"实现。

## 2. USART0 上的字节流分类

同一条线上可能出现以下四类内容，外部设备**必须**能按字节特征区分，不得假设线上只有一种数据。

| 类别 | 起始特征 | 结束特征 | 产生条件 |
|---|---|---|---|
| 下行二进制帧 | `0xA5 0x5A` | 由 `LEN` 字段决定 | 下行内容配置为二进制帧 |
| 下行原报文 | `$` | CRLF | 下行内容配置为原报文（GPS 原样透传） |
| 控制台报告 | `[GPS_DATA]:` | CRLF | 控制台输出为解析模式且逐句打印开启 |
| 控制台文本 | 其它可打印字符 | CRLF | 提示符、命令响应、诊断信息 |

**分类规则（按此顺序判断）**

1. 当前字节为 `0xA5`，则读下一字节：为 `0x5A` 即进入二进制帧解析（见 §3）；否则按普通文本字节处理。
2. 当前字节为 `$`，则按行读取至 CR 或 LF，得到一条 NMEA 语句。
3. 行首为 `[GPS_DATA]:`，则该行是控制台报告（见 §7），机器主机若无需要**应**丢弃。
4. 其余内容按控制台文本处理（见 §6）。

**原子性保证（协议级）**

1. 每一帧二进制帧以单次连续发送完成，**不得**在帧中间插入任何其它字节。
2. 每一条 NMEA 原报文透传块、每一组 6 行控制台报告同样连续发送，不被其它输出截断。
3. 因此外部设备可以依赖"帧内字节连续"这一前提，但**不得**依赖"帧与帧之间没有其它内容"——控制台文本可能出现在两帧之间。

> 现场建议：需要干净的机器数据流时，将控制台设置为 `mode worked` + `verbose 0` + `echo 0`（无报告、无回显、无提示符），线上即只剩二进制帧或原报文。

## 3. 下行二进制帧（`TYPE = 0x01`）

### 3.1 帧结构

```
+-------+-------+-------+-------+---------+----------------+-----------------+
| SOF0  | SOF1  | LEN   | TYPE  | SEQ     | PAYLOAD        | CRC16           |
| 0xA5  | 0x5A  | 1 B   | 1 B   | 2 B 小端| LEN-3 B        | 2 B 小端        |
+-------+-------+-------+-------+---------+----------------+-----------------+
```

| 字段 | 偏移 | 长度 | 规定 |
|---|---|---|---|
| `SOF` | 0 | 2 | 固定 `0xA5 0x5A` |
| `LEN` | 2 | 1 | `TYPE + SEQ + PAYLOAD` 的字节数，不含 `SOF`、`LEN`、`CRC`；`TYPE=0x01` 时恒为 **27**，`TYPE=0x02` 时恒为 **35** |
| `TYPE` | 3 | 1 | 数据类型：`0x01` = 定位数据（§3.2），`0x02` = 终端信息（§3.7），其它值保留 |
| `SEQ` | 4 | 2 | 帧序号，小端，见 §3.4 |
| `PAYLOAD` | 6 | `LEN-3` | `TYPE=0x01` 为 24 字节（§3.2），`TYPE=0x02` 为 32 字节（§3.7） |
| `CRC16` | 30 | 2 | 小端，计算范围 = `LEN` 个字节（`TYPE` 起至 `PAYLOAD` 末） |

**帧总长**：`TYPE = 0x01` 时 32 字节，`TYPE = 0x02` 时 40 字节。接收端**必须**按 `LEN` 计算帧长并按 `TYPE` 分派，**不得**硬编码 32。

### 3.2 PAYLOAD 字段（24 字节，全部小端）

| 载荷偏移 | 帧内偏移 | 字段 | 类型 | 定标 / 单位 | 取值域 |
|---|---|---|---|---|---|
| +0 | 6 | `lat_e7` | int32 | 纬度 × 1e7，单位 1e-7 度 | ±900000000 |
| +4 | 10 | `lon_e7` | int32 | 经度 × 1e7，单位 1e-7 度 | ±1800000000 |
| +8 | 14 | `h_mm` | int32 | 高度 × 1000，单位 mm | ±2147483647 |
| +12 | 18 | `head_cd` | uint16 | 航向 × 100，单位 0.01 度 | 0…36000 |
| +14 | 20 | `base_mm` | uint32 | 基线长度 × 1000，单位 mm | 0…4294967295 |
| +18 | 24 | `sat` | uint8 | 参与解算卫星数 | 0…255 |
| +19 | 25 | `flag` | uint8 | 状态位，见 §3.3 | — |
| +20 | 26 | `t_ms` | uint32 | 帧生成时刻的终端上电毫秒数 | 0…4294967295 |

**编码规则（发送端）**

| 字段 | 规则 |
|---|---|
| `lat_e7`、`lon_e7`、`h_mm` | 乘以定标系数后四舍五入（远离零方向取整）；负值用二进制补码 |
| `head_cd` | 截断取整（`(uint16)(航向 × 100)`）；航向 360.00 度时编码为 36000 |
| `base_mm` | 截断取整（`(uint32)(基线 × 1000)`） |
| `sat` | 截断取整；来源不同口径不同，见 §8.4 |

**接收端解释**

1. `head_cd` 为 36000 时**应**归一化为 0 度（360 度等价）。
2. `h_mm` 的基准随来源句不同：`$GPYBM` 提供椭球高，`$GPNAV` 提供海拔高（见 §8.4）；接收端**应**用 `flag` 的源位决定如何解释。
3. 高度负值表示低于基准面，**不得**按无符号解释。

### 3.3 `flag` 位定义

| 位 | 名称 | 含义 |
|---|---|---|
| bit0 | `VALID` | 1 = 本帧数值有效。判定条件见下 |
| bit1 | `SRC_GPYBM` | 1 = 数据来自 `$GPYBM`；0 = 来自 `$GPNAV` |
| bit2…bit7 | 保留 | 发送端置 0，接收端**应**忽略（不得据此判断版本） |

`VALID = 1` 的判定（发送端解析层，全部满足才置位）：

1. 该语句通过校验和与最小字段数检查；
2. 被使用的字段全部非空且为数字；
3. 数值在物理范围内：纬度 ±90 度、经度 ±180 度、航向 0…360 度；
4. 定位解状态可用（`$GPYBM` ID17 ≠ 0；`$GPNAV` ID19 ≠ 0）；
5. 定向解可用（`$GPYBM` ID18 ≠ 0；`$GPNAV` ID20 文本中不含 `N`）；
6. 卫星数达到终端配置的最少星数（配置项 `sat_min`，默认 4，范围 0…40）。

> 条件 6 意味着 `VALID` 已经包含了星数门槛，接收端**不应**再用 `sat` 自行判一遍。
> `VALID` 与丢帧策略无关：`VALID = 0` 的帧**照常发送**，其数值可能为 0 或为上一次的残留值。接收端**应**用 `VALID` 决定是否采纳。

### 3.4 `SEQ` 语义

1. 每成功发送一帧加 1，取值 0…65535，回绕后继续。
2. **未成功发出的帧不消耗序号**：若一帧因发送失败未上线，其序号由后续帧继续使用。
3. 接收端**应**用序号差值统计丢帧（差值 = 被"保最新"策略丢弃的帧 + 线路错误丢掉的帧）。
4. 同一序号重复出现属异常（重复帧或线路回环），**应**计数并丢弃后到者。

### 3.5 `t_ms` 语义

1. 取值是**终端上电以来的毫秒数**，在生成该帧时采样，不是绝对时间，与接收端时钟不同源。
2. 用途：判断数据年龄与更新间隔、抖动统计。
3. 接收端**不得**把它当作 UTC 或墙钟时间；上电后约 49.7 天回绕一次，比较时**应**按无符号差值处理。

### 3.6 CRC

参数：`poly = 0x1021`、`init = 0xFFFF`、输入输出均不反转、结果不异或（CRC-16/CCITT-FALSE）。
计算范围：`TYPE` 字节起，共 `LEN` 个字节；结果按小端放在帧尾。
参考实现见附录 A。

**标准校验值**：`"123456789"`（9 个 ASCII 字节）→ `0x29B1`。

### 3.7 终端信息帧（`TYPE = 0x02`）

用于对端上电自检、排障与运行记录。**只在被显式索取时发送**（终端命令 `info`），与下行内容、触发方式、速率限制三项配置无关。

| 载荷偏移 | 帧内偏移 | 字段 | 类型 | 含义 |
|---|---|---|---|---|
| +0 | 6 | `uptime_ms` | uint32 | 终端上电毫秒数 |
| +4 | 10 | `version` | uint32 | 固件版本 = `主<<16 ｜ 次<<8 ｜ 修订`；`0x00010200` 表示 1.2.0 |
| +8 | 14 | `tx_frames` | uint32 | 已成功发出的下行帧数（含本类帧） |
| +12 | 18 | `tx_err` | uint32 | 发送失败次数 |
| +16 | 22 | `drop_latest` | uint32 | 因“保最新”被覆盖丢弃的数据份数 |
| +20 | 26 | `gps_ok` | uint32 | 解析成功的语句数 |
| +24 | 30 | `gps_err` | uint32 | 被丢弃的语句数（校验和、格式或字段数不足） |
| +28 | 34 | `out` | uint8 | 当前下行内容：0=关闭，1=原报文，2=二进制帧 |
| +29 | 35 | `auto_mode` | uint8 | 当前触发方式：0=手动，1=新值，2=定时 |
| +30 | 36 | `rate` | uint8 | 当前速率上限（Hz） |
| +31 | 37 | `sat_min` | uint8 | 定位有效所需最少星数 |

计数器均为 uint32，自然回绕；比较**应**按无符号差值处理。本类帧同样消耗 `SEQ`（§3.4）。

**样例 I1（正常运行）**

```
A5 5A 23 02 65 00 91 82 0B 00 00 02 01 00 B4 04
00 00 00 00 00 00 25 00 00 00 6B 09 00 00 03 00
00 00 02 01 01 04 E0 29
```

| 字段 | 值 |
|---|---|
| `LEN` / `TYPE` / `SEQ` | 35 / 0x02 / 101 |
| `uptime_ms` | 754321 |
| `version` | 0x00010200（1.2.0） |
| `tx_frames` / `tx_err` / `drop_latest` | 1204 / 0 / 37 |
| `gps_ok` / `gps_err` | 2411 / 3 |
| `out` / `auto_mode` / `rate` / `sat_min` | 2 / 1 / 1 / 4 |
| `CRC16` | 0x29E0（线上 `E0 29`） |

**样例 I2（下行关闭、尚未发过帧）**

```
A5 5A 23 02 00 00 DC 05 00 00 00 02 01 00 00 00
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
00 00 00 00 01 04 69 0F
```

`SEQ = 0`，`uptime_ms = 1500`，全部计数器为 0，`out = 0`、`auto_mode = 0`、`rate = 1`、`sat_min = 4`，`CRC16 = 0x0F69`。

### 3.8 定位帧样例（`TYPE = 0x01`）

> 以下 4 帧字节均由 §3.1 / §3.2 / §3.6 独立构造并逐字节校验，可直接作为接收端的回归向量。

**S1 一般定位（`$GPYBM` 来源，`VALID` 置位）**

```
A5 5A 1B 01 01 00 87 79 F4 11 B1 57 FB 47 39 30 00 00
11 22 D2 04 00 00 12 03 39 30 00 00 0A 13
```

| 字段 | 值 |
|---|---|
| `LEN` / `TYPE` / `SEQ` | 27 / 0x01 / 1 |
| `lat_e7` | 301234567（30.1234567 度） |
| `lon_e7` | 1207654321（120.7654321 度） |
| `h_mm` | 12345（12.345 m） |
| `head_cd` | 8721（87.21 度） |
| `base_mm` | 1234（1.234 m） |
| `sat` / `flag` | 18 / 0x03（VALID + 源位 1） |
| `t_ms` | 12345 |
| `CRC16` | 0x130A（线上 `0A 13`） |

**S2 未定位（`$GPYBM` 来源，`VALID` 未置位）**

```
A5 5A 1B 01 02 00 00 00 00 00 00 00 00 00 00 00 00 00 00
00 00 00 00 00 03 02 20 4E 00 00 57 9E
```

`SEQ = 2`，数值全 0，`sat = 3`，`flag = 0x02`（仅源位），`t_ms = 20000`，`CRC16 = 0x9E57`。

**S3 南半球、航向上限、序号回绕（`$GPNAV` 来源，`VALID` 置位）**

```
A5 5A 1B 01 FF FF 00 08 D0 EB 48 B5 20 5A 85 EA FF FF
9F 8C 00 00 00 00 19 01 3F 42 0F 00 9D E0
```

`SEQ = 0xFFFF`，`lat_e7 = -338688000`（-33.8688 度），`lon_e7 = 1512093000`，`h_mm = -5499`，`head_cd = 35999`，`base_mm = 0`，`sat = 25`，`flag = 0x01`，`t_ms = 999999`，`CRC16 = 0xE09D`。

**S4 极值边界（`$GPNAV` 来源，序号 0，`VALID` 未置位）**

```
A5 5A 1B 01 00 00 00 08 D0 EB B8 4A DF A5 85 EA FF FF
00 00 FF FF FF FF 00 00 FF FF FF FF 1A 88
```

## 4. 下行原报文模式

### 4.1 内容与界定

终端把模块输出的语句**按行重组后逐条透传**，字节级不做增删改（保留语句自身的 CR/LF）。

1. 一个透传单元 = **一条完整语句**：以 `$` 起，以 `*hh` 与行结束符止，长度 1…1023 字节。
2. 终端在内部按行组装：模块把一条语句分两次发出、或一次发出多条时，终端都会先把语句补完整，再一条一条发出。接收端**不会**收到半条语句。
3. 单元内容通常是模块的数据句，也可能是模块对命令的应答文本；接收端**应**按 `$` 起、`*hh` 止的规则过滤。
4. 行结束符保留模块的原始写法（常见为 CRLF）；接收端**应**同时容忍 CR、LF 与 CRLF。

### 4.2 限制

| 项 | 规定 |
|---|---|
| 单条语句转发上限 | 1023 字节（终端单块上限）；更长的内容会被拆成多帧 |
| 可解析语句长度 | 256 字节；超长语句仍会原样转发，但解析计为失败（`gps_err`） |
| 空行 | 不发送 |
| 长度字段 | 无——原报文模式不带长度前缀，接收端按 CR/LF 界定 |
| 与二进制模式的关系 | 两种内容互斥，由终端配置决定；接收端**应**按 §2 的分类规则同时兼容 |

## 5. 链路语义与时序（下行）

### 4.1 内容

终端把 K922 模块输出的原始字节块按到达顺序透传，字节级不做任何增删改（包括模块回显的命令应答）。

1. 一个透传单元 = 模块一次连续发送的字节块（以模块停止发送为界），长度 1…1023 字节。
2. 内容通常是若干条完整 NMEA 语句（`$…*hh` + CRLF），但**不保证**按语句对齐。接收端**应**按行解析，**不得**假设一个透传单元正好是一条语句。
3. 块内可能出现模块的应答文本（例如命令回显），接收端**应**按 `$` 起、`*hh` 止的规则过滤。

### 4.2 限制

| 项 | 规定 |
|---|---|
| 单元长度上限 | 1023 字节；超出部分丢弃，下一单元重新开始 |
| 空块 | 不发送 |
| 长度字段 | 无——原报文模式不带长度前缀，接收端按 CRLF 界定 |
| 与二进制模式的关系 | 两种内容互斥，由终端配置决定；接收端**应**实现 §2 的分类规则同时兼容 |

## 5. 链路语义与时序（下行）

### 5.1 "保最新"语义（必须理解）

终端**不排队、不应答、不重传、不流控**：

| 行为 | 规定 |
|---|---|
| 缓存 | 只保留一份最新数据（解析值一份、原报文一份） |
| 覆盖 | 上一份尚未发出即被新值覆盖时，旧值**直接丢弃**并计数 |
| 丢弃可见性 | 通过下行序号跳变（§3.4）与终端诊断计数器体现 |
| 结果 | 接收端永远不会收到积压的历史数据；数据延迟不随时间累积 |

### 5.2 触发方式与速率

| 触发配置 | 行为 |
|---|---|
| 手动 | 仅在收到 `fix` 命令时发送一次当前最新值 |
| 新值触发 | 每产生一份新数据即发送，受速率上限限制 |
| 定时触发（心跳） | 每 `1/速率` 秒发送一次最新值，即使数据未更新 |

| 参数 | 范围 | 默认值 |
|---|---|---|
| 速率上限 | 1…20 Hz | 1 Hz |
| 下行内容 | 关闭 / 原报文 / 二进制帧 | 关闭 |

**数据产生速率**：模块被配置为每秒输出 `$GPYBM` 与 `$GPNAV` 各一条，因此"新值触发"下每秒最多产生 2 份解析数据（两帧），**每份数据独立成帧**，`flag` 的源位标明来源。

**带宽参考**（115200 bit/s ≈ 11.5 KB/s）

| 场景 | 单元长度 | 速率 | 占用 |
|---|---|---|---|
| 二进制帧 | 32 B | 1 Hz | 0.03 % |
| 二进制帧 | 32 B | 20 Hz | 0.6 % |
| 原报文，2 条语句 | ≈ 300 B | 1 Hz | 2.6 % |
| 原报文，多语句高频 | ≈ 600 B | 5 Hz | 26 % |

### 5.3 延迟与超时

| 项 | 规定 |
|---|---|
| 单帧传输时间 | 32 B ≈ 2.8 ms（115200 下） |
| 新值触发下的最大延迟 | 1/速率上限 + 传输时间（默认配置下 ≤ 1.03 s） |
| 定时触发下的最大延迟 | 1/速率 + 传输时间 |
| 数据停更判定 | 连续 3 个标称周期（默认 3 s）未收到任何帧，**应**判定链路或定位停更 |
| 超时处理 | 由接收端策略决定（丢弃或沿用最后有效值并标记过期） |

## 6. 上行控制协议

### 6.1 行协议

| 项 | 规定 |
|---|---|
| 行结束符 | CR、LF 或 CRLF 均可；CRLF 只计一次 |
| 行长上限 | 95 个字符（不含行结束符）；超出时**整行丢弃**，终端不给出任何提示 |
| 参数上限 | 11 个参数（不含命令名）；超出的参数被静默忽略，不报错 |
| 分隔符 | 空格或 TAB，连续分隔符视为一个 |
| 引号 | 参数可用双引号括起以包含空格；引号本身不传递给命令 |
| 大小写 | 命令名与参数名**区分大小写**，一律小写 |
| 允许字符 | 可打印 ASCII（0x20…0x7E）；其余字符按 §6.1.1 处理 |
| 命令缩写 | 命令名支持唯一前缀缩写；缩写不唯一时回 `[cli] ambiguous command` |

#### 6.1.1 控制字符行为

| 字符 | 行为 | 机器主机是否可用 |
|---|---|---|
| TAB（0x09） | 补全命令名；`get`/`set` 之后补全配置项名 | 不建议 |
| BS（0x08）/ DEL（0x7F） | 退格编辑 | 不建议 |
| Ctrl+C（0x03） | 丢弃当前行并重新给出提示符 | 可用作"清行" |
| Ctrl+L（0x0C） | 清屏并重画当前行 | 不建议 |
| ESC `[` `A` / `B` | 上/下历史命令（仅在回显开启时生效） | 不建议 |
| 其它控制字符 | 忽略 | — |

### 6.2 机器主机接入要求

1. **应**先关闭回显：`set echo 0` —— 提示符 `> `、输入回显、退格回显都会消失，线上只剩命令响应。
2. 每条命令以 CRLF 结束；终端按行处理，收到行结束符后才开始执行。一条命令**应**在连续的一段字节内发出。
3. **建议串行发送**：终端用 2048 字节环形缓冲接收控制台输入，命令执行期间（例如 `save` 的 Flash 擦写、`reboot`）到达的数据不会丢失；但主机仍**应**等到响应或超时之后再发下一条，不要依赖“连发多条都会被依次执行”。
4. 响应超时**应**不小于 500 ms；`save`（Flash 擦写）与 `reboot` 的响应可能明显更慢，超时**应**放宽到 1 s 以上。
5. 终端输出面向人阅读，**除 §7 的报告外不提供机器可解析的格式保证**；主机**应**忽略无法识别的行。
6. 不要依赖上电后固定出现某条启动文本；主机**应**主动发一条命令（例如 `ver`）来判定终端在线。

### 6.3 命令参考

| 命令 | 参数 | 作用 |
|---|---|---|

| `mode` | `raw` / `worked` | 控制台输出形态（§7.2） |
| `out` | `off` / `raw` / `parsed` | 下行内容 |

#### 6.3.1 `gps` 子命令

| 形式 | 实际发往模块的内容 |
|---|---|

### 6.4 配置项参考

| 配置项 | 范围 | 默认 | 作用 | 生效时机 |
|---|---|---|---|---|
| `mode` | 0 / 1 | 1 | 控制台输出：0 = 模块原报文，1 = 解析报告 | 立即 |
| `echo` | 0 / 1 | 1 | 回显输入与提示符 | 立即 |
| `verbose` | 0 / 1 | 1 | 每句打印一组 `[GPS_DATA]` 报告 | 立即 |
| `sat_min` | 0…40 | 4 | 判定定位有效的最少星数，**仅影响控制台诊断文本** | 立即 |
| `gps_baud` | 9600…921600 | 115200 | 模块串口速率，改动会重配 USART5 | 立即 |
| `out` | 0 / 1 / 2 | 0 | 下行内容：0 = 关闭，1 = 原报文，2 = 二进制帧 | 立即 |
| `auto` | 0 / 1 / 2 | 0 | 下行触发：0 = 手动，1 = 新值，2 = 定时 | 立即 |
| `rate` | 1…20 | 1 | 下行速率上限（Hz） | 立即 |
| `prefix` | 0…126 | 64（`@`） | 上行前缀字符，0 = 关闭前缀路由 | 立即 |

**配置持久化**

1. `save` 把 9 项配置写入 Flash；`load` 取回最近一次保存的值；掉电后未保存的改动丢失。
2. 写入采用追加记录，掉电最多丢失最后一次保存，上一条仍有效。
3. `default` 只改 RAM 中的当前值，需再执行 `save` 才持久。
4. 配置项名称**区分大小写**；数值可用十进制或 `0x` 前缀的十六进制。

### 6.5 前缀路由（`@`）

用于把模块命令直接交给 K922，而不经过终端的命令系统。

| 项 | 规定 |
|---|---|
| 触发 | 行的第一个字节等于 `prefix` 配置值（默认 `@`，0x40） |
| 转发内容 | 前缀之后的整行内容，末尾自动补 CRLF；**前缀字符本身不发送** |
| 限制 | 行长上限同 §6.1（95 字符）；关闭前缀路由时该行按普通命令处理 |
| 回显 | 终端**不回显**已发往模块的内容；模块的应答会经 USART5 进入采集流程（原报文模式下可见） |

示例：发送 `@log com1 gpnav ontime 1` + CRLF → 模块收到 `log com1 gpnav ontime 1` + CRLF。

### 6.6 透明桥模式

桥模式把终端变成 USART0 与 USART5 之间的双向管道，用于现场手工调试模块。

| 项 | 规定 |
|---|---|
| 进入 | 发送 `bridge on`；成功后回 `[cli] bridge ON: ...` |
| 上行 | USART0 收到的每个字节原样发往 USART5，**不解析、不缓冲成行** |
| 下行 | 模块原报文按块发往 USART0（下行临时切为原报文模式，触发为"每个新值"，速率上限 20 Hz） |
| 临时配置 | 进入时临时改写：下行内容 = 原报文、触发 = 新值、速率 = 20、逐句打印 = 关、回显 = 关 |
| 命令 | 桥模式下**不接受命令**（除下述退出序列） |
| 退出 | 静默 ≥ 1 s 后连续收到 3 个 `+`（即 `+++`）；退出序列本身**不转发**给模块 |
| 退出后 | 恢复进入前的全部临时配置，并打印 `[cli] bridge off (...), console back` |
| 复位 | 复位同样可退出（配置不持久保存，见 §6.4） |

**退出序列判定细节**

1. 第一个 `+` 只有在"距上一次转发的字节已静默 ≥ 1000 ms"时才被计入。
2. 计入后连续出现的 `+` 依次累加；出现任何其它字节即清零重新等待。
3. 因此模块数据流中偶然出现的 `+++` 不会被误判为退出。

## 7. 控制台报告 `[GPS_DATA]`

### 7.1 文法

```
<block> ::= <line> ×6
<line>  ::= "[GPS_DATA]:" <name> ":" <value> CRLF
<value> ::= [-] <digits> "." <6 digits>     ; 相当于 printf("%f")
          | <digits>                        ; GPS_Satellite，相当于 printf("%d")
```

### 7.2 行定义与输出条件

| 序号 | 行首 | 值来源 | 单位 |
|---|---|---|---|
| 1 | `[GPS_DATA]:latitude:` | 纬度 | 度 |
| 2 | `[GPS_DATA]:longitude:` | 经度 | 度 |
| 3 | `[GPS_DATA]:ElpHeight:` | 高度 | m |
| 4 | `[GPS_DATA]:Heading_Angle:` | 航向 | 度 |
| 5 | `[GPS_DATA]:Baseline:` | 双天线基线长 | m |
| 6 | `[GPS_DATA]:GPS_Satellite:` | 参与解算卫星数 | 颗 |

**输出条件**：控制台输出形态为"解析"且逐句打印开启时，每解析到一句**通过校验**的语句输出一组 6 行，顺序固定，整组连续发送。

| 控制台形态 | 逐句打印 | USART0 上的控制台内容 |
|---|---|---|
| 原报文 | 任意 | 模块原报文（按块，含 CRLF） |
| 解析 | 开 | 每组 6 行 `[GPS_DATA]` 报告 |
| 解析 | 关 | 仅命令响应，无报告 |

**示例（一组）**

```
[GPS_DATA]:latitude:27.852472
[GPS_DATA]:longitude:112.965327
[GPS_DATA]:ElpHeight:55.516000
[GPS_DATA]:Heading_Angle:122.537000
[GPS_DATA]:Baseline:0.951000
[GPS_DATA]:GPS_Satellite:22
```

### 7.3 有效性约定（重要）

1. 报告只含数值，**不含状态**：`0.000000` 既可能是真实零值，也可能是该项无效（例如定向未定位时航向与基线本就是 0）。
2. 需要区分"真实零"与"无效"时，**应**使用下行二进制帧的 `flag` bit0（§3.3），不要用数值是否为零来判断。
3. 本报告的值与同一时刻二进制帧的值同源，但两者是**独立交付**的：报告受 `mode`/`verbose` 控制，帧受 `out`/`auto`/`rate` 控制，接收端**不得**假定二者成对出现。

## 8. 模块侧接口（USART5 / K922）

### 8.1 语句格式

```
$<语句名>,<字段2>,<字段3>,…,<字段N-1>,*<校验和><CR><LF>
```

| 项 | 规定 |
|---|---|
| 起始符 | `$` |
| 字段分隔 | `,`（0x2C） |
| 字段号 | 从 1 开始，**字段 1 是语句名本身**（含 `$`） |
| 校验和 | `*` 后接 2 位十六进制大写；值为 `$` 之后、`*` 之前所有字节的逐字节异或 |
| 结束符 | CRLF |
| 空字段 | 连续两个逗号表示该字段无效（**不等于数值 0**） |
| 字段内容 | 不得按固定字符数截取，必须按逗号位置取 |

终端使用的两种语句：`$GPYBM`（手册 3.3.1.4.4）、`$GPNAV`（手册 3.3.1.4.5）。

### 8.2 终端开机下发的模块配置

上电后终端按以下顺序向模块发送（每条以 CRLF 结束）：

| 顺序 | 内容 | 作用 |
|---|---|---|
| 1 | `unlogall` | 清除模块内已有的输出注册，避免重复输出 |
| 2 | `set appscene survey` | 选择测量场景 |
| 3 | `log com1 gpnav ontime 1` | `$GPNAV` 每秒输出一条 |
| 4 | `log com1 gpybm ontime 1` | `$GPYBM` 每秒输出一条 |

**终端不发送 `freset`**：该命令会清除模块内已保存的配置并强制冷启动重收敛，显著延长首次定位时间。

### 8.3 `$GPYBM` 使用字段

| ID | 含义 | 单位 / 格式 | 终端用途 |
|---|---|---|---|
| 4 | 纬度（北正南负） | 度，9 位小数 | 位置 |
| 5 | 经度（东正西负） | 度，9 位小数 | 位置 |
| 6 | 椭球高 | m，3 位小数 | 高度 |
| 7 | 航向角（真北基准，顺时针） | 0…360 度 | 航向 |
| 17 | 定位解状态（0 无效 / 1 单点 / 4 固定 / 5 浮点） | 整数 | 有效性判定 |
| 18 | 定向解状态（0 未定位 / 1 / 4 / 5） | 整数 | 有效性判定 |
| 19 | 主站天线收星数 | 整数 | 卫星数 |
| 22 | 双天线基线长 | m，3 位小数 | 基线 |

最小字段数：**23**（不足则整句丢弃）。

### 8.4 `$GPNAV` 使用字段

| ID | 含义 | 单位 / 格式 | 终端用途 |
|---|---|---|---|
| 7 | 纬度 | 度，11 位小数 | 位置 |
| 8 | 经度 | 度，11 位小数 | 位置 |
| 9 | 海拔高（大地水准面之上） | m，4 位小数 | 高度 |
| 10 | 高程异常值 N | m，4 位小数 | 单位换算校核 |
| 12 | 航向角（真北基准） | 0…360 度 | 航向 |
| 19 | RTK 定位状态（0 无效 / 1 单点 / 2 差分 / 3 浮点 / 4 固定） | 整数 | 有效性判定 |
| 20 | 航向解指示（`NN`/`NV`/`VN`/`VV`，`V` = 有效） | 2 字符 | 有效性判定 |
| 22 | 基线长 | m，3 位小数 | 基线 |
| 23…27 | 参与解算星数（多系统，逗号分隔，可空） | 整数 | 卫星数 = 各非空值之和 |

最小字段数：**22**（不足则整句丢弃）。

**字段映射与口径**

| 输出量 | `$GPYBM` 来源 | `$GPNAV` 来源 |
|---|---|---|
| 纬度 / 经度 | ID4 / ID5 | ID7 / ID8 |
| 高度 | ID6（**椭球高**） | ID9（**海拔高**） |
| 航向 | ID7 | ID12 |
| 基线 | ID22 | ID22 |
| 卫星数 | ID19（主站收星数） | ID23…27 各非空值之和 |

1. **高度基准不同**：椭球高 = 海拔高 + 高程异常值 N，N 见 `$GPNAV` ID10。同一次定位的两种来源可用
   `$GPYBM.ID6 ≈ $GPNAV.ID9 + $GPNAV.ID10` 交叉校验（实测 `55.516 ≈ 71.7937 + (-16.2776)`）。
2. **卫星数口径不同**：`$GPYBM` 是主站天线收星数，`$GPNAV` 是多系统参与解算星数之和，两者不可混用比较。
3. **定向有效性判据不同**：`$GPYBM` 用 ID18（整数，0 = 无定向解）；`$GPNAV` 用 ID20 文本（含 `N` 即无定向解）。

### 8.5 解析规则（终端强制）

| 条件 | 处理 |
|---|---|
| 无 `$` 起始、无 `*` 校验字段 | 丢弃该句 |
| 校验和与 `*` 后两位不符 | 丢弃该句 |
| 字段数不足（`$GPYBM` < 23、`$GPNAV` < 22） | 丢弃该句 |
| 使用字段为空或非数字 | 该字段无效，整句有效性置 0 |
| 数值超出物理范围 | 整句有效性置 0 |
| 一个接收块内含多条语句 | 逐句处理，各成一组输出 |

### 8.6 许可的模块命令入口

| 入口 | 说明 |
|---|---|
| 前缀路由 | 行首 `@` + 命令（§6.5），适合逐条精确下发 |
| `gps` 命令 | 常用操作的封装（§6.3.1） |
| 透明桥 | 手工交互调试（§6.6） |
| 开机自动 | §8.2 的 4 条固定命令 |

## 9. 异常处理与重同步

### 9.1 下行接收端

| 情况 | 处理 |
|---|---|
| 校验和错 | 丢弃整帧，回到 `SOF` 搜索状态；**不得**尝试修补 |
| `LEN` 非法（< 3 或 > 40） | 丢弃并重同步 |
| `TYPE` 未知 | 按 `LEN` 跳过该帧，**不得**按定位帧解释 |
| 帧内出现 `0xA5` 后非 `0x5A` | 判为假帧头，重同步 |
| 序号跳变 | 统计丢帧，继续使用后续帧 |
| 序号重复 | 视为异常（重复帧或回环），丢弃后到者并计数 |
| 连续 3 个周期无帧 | 判定数据停更，按 §5.3 处理 |
| 接收缓冲溢出 | 丢弃当前帧并重同步，计数 |

### 9.2 上行主机

| 情况 | 终端响应 |
|---|---|
| 未知命令 | `[cli] unknown command '<词>', try 'help'`，并给出前两个字符相同的命令提示 |
| 命令缩写有歧义 | `[cli] ambiguous command '<词>', try 'help'` |
| 参数越界或缺失 | `[cli] usage: …`（不改变任何配置） |
| 行超过 95 字符 | 整行丢弃，无任何输出 |
| 参数超过 11 个 | 超出部分静默忽略，命令按前 11 个参数执行 |
| 已移除的命令（`gps reset`） | 回提示并列替代命令，不做任何动作 |
| 配置项名称错误 | `[cli] no such command or item '<词>'` |
| 平台功能未实现 | `[cli] … : hook not implemented` |

### 9.3 链路质量判据

| 指标 | 来源 | 判据建议 |
|---|---|---|
| 丢帧率 | 下行序号差值 / 收到帧数 | 稳态下应为 0；`auto=fix` 且速率受限时出现跳变属预期 |
| 校验失败率 | 接收端 CRC 失败计数 | 持续非 0 说明线路干扰或波特率偏差 |
| 数据年龄 | 接收端本地时间与 `t_ms` 差值 | 超过 3 个标称周期应告警 |
| 报告与帧一致性 | 同一时刻报告值与帧值 | `flag` 的源位决定高度的基准，比较时须先换算 |

## 附录 A CRC-16/CCITT-FALSE 参考实现

```c
/* 输入指向 TYPE 字节，len = LEN 字段的值 */
static uint16_t crc16_ccitt_false(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFFU;
    uint16_t i;
    uint8_t  b;

    for (i = 0U; i < len; i++) {
        crc ^= (uint16_t)((uint16_t)data[i] << 8);
        for (b = 0U; b < 8U; b++) {
            crc = (0U != (crc & 0x8000U))
                    ? (uint16_t)((uint16_t)(crc << 1) ^ 0x1021U)
                    : (uint16_t)(crc << 1);
        }
    }
    return crc;
}
```

自测：`"123456789"` → `0x29B1`；§3.7 的 4 个样例帧可直接作为回归向量。

## 附录 B 下行接收参考实现

```c
/* 逐字节喂入（中断或轮询均可）；同时兼容二进制帧与 NMEA 文本行 */
typedef struct {
    uint8_t  buf[64];
    uint16_t idx;                 /* 已收字节数；0 = 等待帧头 */
    uint16_t expect;              /* 一帧总长 = 2 + 1 + LEN + 2 */
    char     line[160];           /* NMEA 文本行缓冲 */
    uint16_t line_len;
} rx_t;

static void rx_feed(rx_t *rx, uint8_t b)
{
    /* —— 二进制帧状态机 —— */
    if (0U == rx->idx) {
        if (0xA5U == b) { rx->buf[rx->idx++] = b; return; }
    } else if (1U == rx->idx) {
        if (0x5AU == b) { rx->buf[rx->idx++] = b; return; }
        rx->idx = (0xA5U == b) ? 1U : 0U;     /* 假帧头：重同步 */
        if (1U == rx->idx) { rx->buf[0] = 0xA5U; }
        return;
    } else {
        if (rx->idx >= sizeof(rx->buf)) { rx->idx = 0U; return; }
        rx->buf[rx->idx++] = b;
        if (2U == rx->idx) {                   /* LEN 到手 */
            if ((b < 3U) || (b > 40U)) { rx->idx = 0U; return; }
            rx->expect = (uint16_t)(2U + 1U + b + 2U);
        }
        if (rx->idx == rx->expect) {
            uint8_t  len = rx->buf[2];
            uint16_t crc = crc16_ccitt_false(&rx->buf[3], len);
            uint16_t got = (uint16_t)(rx->buf[3 + len] |
                                      ((uint16_t)rx->buf[4 + len] << 8));
            if (crc == got) {
                /* rx->buf[3] = TYPE, [4..5] = SEQ, [6..] = PAYLOAD */
            }
            rx->idx = 0U;                      /* 无论成败都重同步 */
            return;
        }
    }

    /* —— NMEA 文本行（原报文模式）—— */
    if ((0U == rx->idx) && (0U != rx->line_len || '$' == b || '\n' == b || '\r' == b)) {
        if (('\r' == b) || ('\n' == b)) {
            if (rx->line_len > 0U) {
                rx->line[rx->line_len] = '\0';
                /* 交给行处理（校验 XOR、过滤 $…*hh） */
                rx->line_len = 0U;
            }
        } else if (rx->line_len < (sizeof(rx->line) - 1U)) {
            rx->line[rx->line_len++] = (char)b;
        } else {
            rx->line_len = 0U;                 /* 行过长：丢弃 */
        }
    }
}
```

**要点**

1. 只在 `idx == 0` 时等待 `0xA5`；`0xA5` 之后的字节非 `0x5A` 时归零重同步——原报文里同样可能出现 `0xA5`，必须两字节判头。
2. `LEN` 先做范围检查（3…40）再计算总长，防止野长度写越界。
3. 校验失败直接丢帧，不做修补、不请求重传（协议不提供重传）。
4. 两种内容可共存于同一线路，按 §2 的分类顺序处理即可。

## 附录 E 接入检查清单

接收端固件按本规范实现后，逐项确认：

| # | 检查项 | 判据 |
|---|---|---|
| 1 | 串口参数 | 115200-8-N-1，无流控 |
| 2 | 帧同步 | 只在 `0xA5` 之后跟 `0x5A` 时进入帧解析；`0xA5` 后非 `0x5A` 立即重同步 |
| 3 | 长度校验 | 读出 `LEN` 后先判 `3 ≤ LEN ≤ 40`，再按 `2+1+LEN+2` 收满整帧 |
| 4 | CRC | CRC-16/CCITT-FALSE 覆盖 `TYPE` 起 `LEN` 个字节，与帧尾小端值比对 |
| 5 | 类型分派 | `0x01` 按 §3.2 解释，`0x02` 按 §3.7 解释，未知类型按 `LEN` 跳过 |
| 6 | 位域解释 | 只解释 `flag` 的 bit0/bit1，其余位忽略 |
| 7 | 序号统计 | 用 `SEQ` 差值统计丢帧；同一 `SEQ` 重复出现计为异常 |
| 8 | 时间语义 | `t_ms`/`uptime_ms` 只当终端上电计时，不与本地时钟混算 |
| 9 | 原报文模式 | 能同时吃 §3 的帧与 §4 的整条语句文本，按 §2 的分类顺序处理 |
| 10 | 无流控假设 | 不做应答、不重传、不等待；处理不过来就丢弃并由 `SEQ` 体现 |
| 11 | 自检 | 用 §3.7 / §3.8 的样例帧做回归，解码结果与文档表格一致 |
| 12 | 在线判定 | 连续 3 个标称周期（默认 3 s）无帧即判数据停更，并区分“未配置下行”与“链路故障” |

### F.3 端到端联调

1. 置 `out parsed`、`auto fix`、`rate 1`，控制台 `set verbose 0`、`set echo 0`；
2. 接收端运行 30 分钟，记录：帧总数、`SEQ` 跳变次数、CRC 失败次数、`t_ms` 数据年龄；
3. 与终端 `gstat` 的 `dropped(latest)` 对比：跳变次数应约等于丢弃数 + 线路错误数；
4. 发 `info` 命令，核对信息帧中的 `tx_frames`、`gps_ok`、`gps_err` 与 `gstat`/`status` 显示一致；
5. 切 `out raw`，确认每个透传单元都是一条以 `$` 开头、`*hh` 结尾的完整语句。
